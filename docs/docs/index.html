项目简介

NeoTask 是一个纯 Python 实现的轻量级异步任务调度系统，专为耗时任务（AI 生成、视频处理、数据爬取等）设计。无需部署 Redis、PostgreSQL 等外部服务，安装后即可在任意 Python 项目中直接使用。

核心特性

特性 说明
嵌入式轻量 纯 Python 异步任务池，嵌入应用进程，无需部署外部服务（v1.0.2 基础依赖仅 aiosqlite/croniter，最低版本 Python ≥ 3.8，依赖清单见系列“为什么我不用 Celery 做轻量任务调度”篇）
即时任务 提交后立即执行，支持四级优先级（TaskPriority）
定时任务 支持延时执行、指定时间点、固定间隔、Cron 表达式
自动重试 执行异常自动重试（max_retries 内线性退避）
持久化存储 内存/SQLite/Redis 三种存储后端，同一存储抽象
事件回调 7 类生命周期事件订阅（created/started/completed/failed/cancelled/progress/reclaimed）
分布式支持 Redis 后端 + 心跳/回收/锁，对等节点去中心化消费

⚠️ 能力边界：NeoTask 没有 DAG 工作流编排（WorkflowEngine 是 v1.5 路线图规划，尚未实现）、没有多租户/配额；Web UI 为独立装配组件（neotask[ui] extra，TaskPool 不自动挂载）。分布式能力（Redis 后端 + 心跳/回收/锁）与死信队列均已就位，详见核心功能与架构设计。

快速上手

安装

# 基础安装
pip install neotask

# 带 Redis 分布式支持
pip install neotask[redis]

# 加装 Web UI 扩展（fastapi/uvicorn 等，可选）
pip install "neotask[ui]"

# 完整安装（包含所有扩展）
pip install neotask[full]

即时任务

from neotask import TaskPool

async def process_order(data):
    """处理订单"""
    print(f"处理订单: {data['order_id']}")
    return {"status": "success"}

# 创建任务池
pool = TaskPool(executor=process_order)

# 提交任务
task_id = pool.submit({"order_id": "12345"})

# 等待结果
result = pool.wait_for_result(task_id)

# 关闭
pool.shutdown()

定时任务

from neotask import TaskScheduler

scheduler = TaskScheduler(executor=process_order)

# 延时 60 秒执行
scheduler.submit_delayed({"order_id": "123"}, delay_seconds=60)

# 每 5 分钟执行一次
scheduler.submit_interval({"task": "heartbeat"}, interval_seconds=300)

# 每天 9 点执行
scheduler.submit_cron({"task": "daily"}, cron_expr="0 9 * * *")

scheduler.shutdown()

工作流编排（路线图，尚未实现）

⚠️ v1.0.2 没有 WorkflowEngine / TaskNode / WorkflowDefinition，也没有任何 DAG 编排模块。任务编排是 v1.5 的规划能力，设计推演见任务编排详解。

当前需要"多任务串联"时，请在业务层自行编排：任务 A 的 executor 内 submit 任务 B，配合 wait_for_result 做门控。

常见问题

Q: NeoTask 需要外部服务吗？

A: 不需要。基础版本使用内存或 SQLite（Python 内置），无需安装 Redis 或 PostgreSQL。

Q: 支持分布式部署吗？

A: 支持。构造 TaskPoolConfig.redis("redis://localhost:6379") 即切换 Redis 存储，多节点对等消费共享队列；回收、心跳与死信链路均已就位，详见故障恢复。

Q: 任务失败后会自动重试吗？

A: 会。可配置 max_retries 和 retry_delay 参数。

Q: 如何监控任务执行情况？

A: 支持事件回调，可监听任务创建、开始、完成、失败等事件（7 类订阅：on_created/on_started/on_completed/on_failed/on_cancelled/on_progress/on_reclaimed）。内置 WebUIServer 组件（v1.0.2 存在，neotask[ui] extra）可自行装配启动，但 TaskPool 默认不挂载，详见节点监控。

Q: 性能如何？

A: 10 Workers、100ms 耗时任务的理论吞吐上限约 100 tasks/s（表见上文“性能参考”）。官方基准脚本的实测数据与“队列裸测与端到端相差两个数量级”等结论，见性能基准详解。

├── core/                     # 生命周期/分发/事件/未来管理
├── queue/                    # 优先级队列 + 延时队列 + 队列调度器
├── scheduler/                # 周期任务管理 + cron 解析 + 时间轮（enable_time_wheel 可选开启）
├── worker/                   # Worker 池 + 回收器（心跳在 core/heartbeat.py）
├── storage/                  # memory/sqlite/redis 三存储
├── lock/                     # 分布式锁（Redis + Lua）
├── distributed/              # 节点管理/协调器（coordinator 预留，未接入主链路）
├── metrics/                  # 指标采集/健康检查
├── webui/                    # Web UI 服务（neotask[ui] extra，需自行装配）
└── event/                    # 事件总线与处理器

注：源码中没有 workflow/（DAG）与 api/workflow_engine.py——DAG 编排是 v1.5 路线图规划；真实 16 个子包清单见架构设计与核心功能。
