二、三分钟通关：最小可用链路

NeoTask 的使用心智模型只有四步：定义执行器 → 建池 → 提交 → 等待。

第 1 步：定义任务执行器

执行器就是一个"吃 dict、吐 dict"的 async 函数（同步函数也支持，会被执行器包装）：

# 📝 示例代码
import asyncio

async def process_image(data: dict) -> dict:
    """处理图片：模拟下载+压缩+上传"""
    print(f"处理图片: {data['url']}")
    await asyncio.sleep(1)          # 模拟耗时
    return {"status": "success", "size": 1024}

第 2 步：创建任务池并提交

# 📝 示例代码
from neotask import TaskPool

pool = TaskPool(executor=process_image)      # 只需传执行器
task_id = pool.submit({"url": "https://example.com/a.jpg"})
print(f"任务已提交: {task_id}")
# 输出形如: TSK2026090901010201234567 之类的时间戳+随机ID

🔧 关键行为：submit() 内部会调用 _ensure_running()——第一次提交时任务池自动启动（api/task_pool.py:482），无需手动 start()。任务池在独立线程的事件循环中运行，submit 通过 run_coroutine_threadsafe 投递任务后同步返回 task_id。

第 3 步：等待结果并关闭

# 📝 示例代码
result = pool.wait_for_result(task_id, timeout=30)   # 同步阻塞等待（默认超时 300s）
print(f"任务结果: {result}")                          # {'status': 'success', 'size': 1024}
pool.shutdown()                                      # 优雅关闭，等待在跑任务结束

🔧 补充事实：wait_all(task_ids) 也是同步 API，但它逐个串行等待且内部吞掉超时——某个任务等待超时不会抛异常，而是以 {"error": "..."} 字典形式出现在结果里（api/task_pool.py:537）。

三、三种使用范式

范式 A：同步风格（脚本/服务初始化用）

# 📝 示例代码
from neotask import TaskPool

pool = TaskPool(executor=process_image)
pool.submit({"url": "a.jpg"})
task_id = pool.submit({"url": "b.jpg"}, priority=1)   # 数字越小越先执行
result = pool.wait_for_result(task_id, timeout=60)
pool.shutdown()

范式 B：异步风格（在 async 应用内混用）

# 📝 示例代码
import asyncio
from neotask import TaskPool

async def main():
    pool = TaskPool(executor=process_image)
    pool.start()                                        # 显式启动

    task_id = await pool.submit_async({"url": "a.jpg"}) # async 版本
    result = await pool.wait_for_result_async(task_id)
    print(result)

    pool.shutdown()                                     # ⚠️ 没有 shutdown_async！
    # 同步 shutdown 内部通过 run_coroutine_threadsafe 投递,在异步代码中同样可用

asyncio.run(main())

⚠️ 易错点：网上资料流传的 await pool.shutdown_async() 不存在（1.0.2 无此 API，会抛 AttributeError）。同步/异步 API 的对偶关系仅存在于 submit/wait/查询族，生命周期方法 start()/shutdown() 只有同步版本。

范式 C：上下文管理器（最简洁，推荐入门）

# 📝 示例代码
from neotask import TaskPool

with TaskPool(executor=process_image) as pool:   # __enter__ 自动 start
    task_id = pool.submit({"url": "a.jpg"})
    result = pool.wait_for_result(task_id)
    print(result)
# __exit__ 自动优雅 shutdown

🔧 三种范式背后的统一事实：__enter__ 调 start()、__exit__ 调 shutdown()（api/task_pool.py:444），所以范式 A 不写 start() 也能跑——是 submit 的自动启动兜底，而不是"不需要启动"。

四、提交选项速查

submit 的完整签名（🔧 api/task_pool.py:473，async 版本同参）：

submit(data: dict, task_id: str | None = None,
       priority: int | TaskPriority = TaskPriority.NORMAL,
       delay: float = 0, ttl: int = 3600) -> str
参数 默认 说明 详见
task_id 自动生成 自定义 ID；重复会抛 TaskAlreadyExistsError —
priority NORMAL 0~3 四级（CRITICAL/HIGH/NORMAL/LOW），支持枚举或数字 优先级任务
delay 0 延迟秒数，>0 走延迟通道 延时任务
ttl 3600 双语义：执行超时 + 终态保留时长 持久化

批量与优先级示例（📝）：

from neotask import TaskPool, TaskPriority

with TaskPool(executor=process_image) as pool:
    # 批量提交（同一优先级）
    ids = pool.submit_batch([
        {"url": "1.jpg"}, {"url": "2.jpg"}, {"url": "3.jpg"},
    ], priority=TaskPriority.HIGH)

    # 单个提交时指定优先级（枚举或数字等价）
    pool.submit({"url": "urgent.jpg"}, priority=TaskPriority.CRITICAL)  # 或 priority=0

    # 等待全部完成（串行逐个等待，见上文说明）
    results = pool.wait_all(ids)

🔧 优先级枚举真实定义：CRITICAL=0 / HIGH=1 / NORMAL=2 / LOW=3（models/task.py），数字越小越先出队；非法数字（如 7）在 dispatcher 转枚举时会抛 ValueError。

五、定时任务：TaskScheduler

TaskScheduler 是 TaskPool 的超集——内部持有一个 TaskPool，在其上叠加延时 / 指定时刻 / 周期 / Cron 四类提交（🔧 api/task_scheduler.py）：

# 📝 示例代码
from neotask import TaskScheduler
from datetime import datetime, timedelta

async def send_report(data: dict) -> dict:
    print(f"发送报表: {data['type']}")
    return {"status": "sent"}

scheduler = TaskScheduler(executor=send_report)   # 构造即含底层 TaskPool

# 1. 延时 60 秒后执行一次
scheduler.submit_delayed({"type": "remind"}, delay_seconds=60)

# 2. 指定时刻执行一次（内部换算成延时秒数）
scheduler.submit_at({"type": "once"}, execute_at=datetime.now() + timedelta(minutes=5))

# 3. 每 5 分钟执行一次（首次执行时机见下方提示）
scheduler.submit_interval({"type": "heartbeat"}, interval_seconds=300)

# 4. Cron 表达式周期执行（依赖 croniter）
scheduler.submit_cron({"type": "daily"}, cron_expr="0 9 * * *")

scheduler.shutdown()

定时任务的三个真实行为（对照源码）

  1. 延时任务：submit_delayed 直接委托底层 pool.submit(delay=delay_seconds)，到期触发依赖内存堆 + 事件循环调度；触发计划不落库，重启即失（详见 延时任务）。

  2. 周期任务首次执行：submit_interval 的 run_immediately 默认 True，控制首次是否立即执行；若传入未来的 start_at，则指定时刻优先（🔧 scheduler/periodic.py）。

  3. 周期/Cron 任务是"计划"而非"任务"：每次触发会向底层池提交一个全新 task_id 的即时任务；wait_for_result 等的是单次执行结果。取消请用 scheduler.cancel(name/id) 类接口（周期任务名可通过 name 参数指定，便于管理）。

六、事件回调：监听任务生命周期

事件回调注册在 TaskPool 上（🔧 api/task_pool.py:813，handler 是 async 函数、收 TaskEvent）：on_created / on_started / on_completed / on_failed / on_cancelled / on_progress / on_reclaimed。

# 📝 示例代码
from neotask import TaskPool

async def my_task(data):
    return {"result": "done"}

async def on_completed(event):
    print(f"完成: {event.task_id}, 结果: {event.data}")

async def on_failed(event):
    print(f"失败: {event.task_id}, 错误: {event.data}")

with TaskPool(executor=my_task) as pool:
    pool.on_completed(on_completed)
    pool.on_failed(on_failed)
    pool.submit({"id": 1})

🔧 说明：事件在任务池内部的事件总线上异步分发，回调与指标收集同链路；event.data 的内容因事件而异（completed 带 result、failed 带 error、progress 带 progress/message/timestamp）。回调异常会被总线捕获，不影响任务主流程——别指望回调抛错能阻断任务。

七、存储与部署档位切换

默认配置是内存存储（开发友好、重启即失）。三个工厂方法一键切换（🔧 models/config.py，真实签名）：

# 📝 示例代码
from neotask import TaskPool, TaskPoolConfig

# 单机生产：SQLite 持久化到本地文件
pool = TaskPool(executor=process_image,
                config=TaskPoolConfig.sqlite(path="neotask.db"))

# 分布式生产：Redis（唯一启用去中心化组件集群的档位）
pool = TaskPool(executor=process_image,
                config=TaskPoolConfig.redis(url="redis://localhost:6379"))

pool.submit({"url": "a.jpg"})
pool.shutdown()
档位 数据存活 多进程/多节点 典型场景
memory（默认） 进程重启即失 ❌ 开发测试
sqlite 磁盘文件 ⚠️ 仅单进程（多进程有重复领取窗口） 单机生产
redis 独立服务 ✅ 完整分布式 集群生产

⚠️ 切档前必读 持久化：SQLite 档勿开多进程；Redis 档需同配 lock_type="redis"（默认锁类型是 memory，与存储档位独立）。完整参数表见 配置说明。

八、完整示例：批量图片处理服务

# 📝 示例代码
import asyncio
from neotask import TaskPool, TaskPriority

async def process_image(data: dict) -> dict:
    """处理图片：下载 -> 压缩 -> 上传（模拟）"""
    url = data['url']
    print(f"[1/3] 下载: {url}"); await asyncio.sleep(0.5)
    print(f"[2/3] 压缩: {url}"); await asyncio.sleep(0.5)
    print(f"[3/3] 上传: {url}"); await asyncio.sleep(0.5)
    return {"status": "success", "url": url,
            "compressed_size": data.get('size', 1024) // 2}

async def batch_process():
    images = [
        {"url": "https://example.com/img1.jpg", "size": 2048},
        {"url": "https://example.com/img2.jpg", "size": 3072},
        {"url": "https://example.com/img3.jpg", "size": 1536},
    ]
    with TaskPool(executor=process_image, config=TaskPoolConfig.memory()) as pool:
        task_ids = []
        for i, img in enumerate(images):
            # 第一张图高优先级
            pri = TaskPriority.HIGH if i == 0 else TaskPriority.NORMAL
            task_ids.append(pool.submit(img, priority=pri))

        results = pool.wait_all(task_ids)
        for tid, r in results.items():
            print(f"{tid}: {r}")

asyncio.run(batch_process())

九、常见问题

Q: 同步 API 和异步 API 怎么选？

A: 两者行为等价（都会自动启动）。submit()/wait_for_result() 是线程安全的同步包装——内部把协程投递到任务池的事件循环线程并阻塞等待结果，适合普通脚本与 Web 框架同步代码；submit_async()/wait_for_result_async() 适合 async 应用内联使用，避免阻塞线程。生命周期方法没有 async 版本（没有 shutdown_async）。

Q: 任务池需要手动 start() 吗？

A: 不需要。第一次 submit/submit_async 会通过 _ensure_running() 自动启动（🔧 api/task_pool.py:295）。start() 存在的意义是提前初始化（如配合周期任务注册）；上下文管理器自动 start/shutdown。

Q: 任务失败会自动重试吗？

A: 会，但有精确边界（🔧 worker/pool.py:372）：执行器抛异常或超时时，若 retry_count < max_retries（默认 3），任务回到 PENDING 并以 retry_delay × 新重试次数 的递增延迟重新入队（1s/2s/3s…）；超过上限才置 FAILED。注意：通过 pool.cancel() 取消的任务不走重试。每次重试都会发布 task.retry 事件并计入指标（avg_retry_count），监控面可见，详见 节点监控。

Q: 任务超时怎么设置？

A: TaskPoolConfig(task_timeout=30)（默认 None=不限制）。超时用 asyncio.wait_for 实现（🔧 pool.py:302），超时走失败处理链路：未超重试上限 → 按递增延迟重试；超上限 → FAILED。注意 ttl 是另一个独立概念（提交级参数），别混淆。

Q: 如何选择存储类型？如何监控运行状态？

A: 存储按 第七节 三档切换。监控三件套：事件回调（业务感知）、pool.get_stats()（队列深度 + 各状态计数 + 指标摘要）、pool.get_worker_stats() / get_health_status()（Worker 明细与健康视图）。get_health_status() 为读时刷新——结果在 HEALTH_CHECK_TTL=5.0 秒内直接复用缓存，超时即重新执行检查；enable_health_check=False 时结果不含 checks 键。详见 节点监控。

Q: 提交队列满了会怎样？

A: 队列上限 queue_max_size=10000（内存/Redis 队列通用）。队列满时 TaskDispatcher.dispatch 会抛出 QueueFullError（neotask.common.exceptions.QueueFullError，已导出）——调用方直接拿到异常，按可重试错误处理即可，不会留下静默滞留的任务。详见 优先级任务 故障场景。

Q: Web UI 可用吗？

A: WebUIServer（FastAPI，/api/stats 端点）是独立组件，v1.0.2 不会自动启动——需 pip install neotask[ui] 后自行实例化。开箱即用的面板不存在，请先依赖事件回调 + get_stats 自建可观测性。
