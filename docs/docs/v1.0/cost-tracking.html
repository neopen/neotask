成本与耗时

上报 token、API 调用与预估费用，读取排队/执行耗时，并聚合跨任务成本。

v1.0 · NeoTask 1.x 更新于 2026-11-22 约 6 分钟 读完 GitHub

1.1 起，任务记录会保存执行耗时与业务成本。耗时由 NeoTask 自动计算；成本需要执行器主动上报 token、API 调用次数与预估费用。NeoTask 只做累加与查询，不负责定价、计费或对账。

自动耗时字段

字段计算方式何时写入
queue_wait_msstarted_at - created_at任务开始执行时
duration_mscompleted_at - started_at进入终态时

两个字段出现在 get_result() 与 get_task() 的返回中。任务重试时计时会重新开始，旧一轮的数值被覆盖；成本则相反，历次执行的消耗都会累加。

上报成本

from neotask import report_cost

async def llm_task(data):
    response = await call_model(data["prompt"])
    report_cost(
        tokens_in=120,
        tokens_out=48,
        api_calls=1,
        estimated_cost=0.0012,
        currency="USD",
    )
    return {"text": response}

report_cost() 是同步函数，在异步任务与线程执行的同步任务中都可直接调用，不需要 await。进程执行器拿不到该上下文，改为在父进程调用 pool.report_cost(task_id, ...)。

参数默认值说明
tokens_in / tokens_out0输入与输出 token 数，累加
api_calls0外部 API 调用次数，累加
estimated_costNone本次费用金额；None 时只累加其它字段
currencyNone币种标识，如 USD
  • 多次上报按字段累加，任务记录中的 estimated_cost 是总额，cost_tracking 保存明细与币种。
  • 币种以首次上报为准；同一任务内出现不同币种时标记为 MIXED，避免把不同币种金额静默相加。
  • 终态任务仍接受追加成本，适合父进程在子任务结束后才拿到用量数据的场景。
  • 执行器内上报返回 bool；不在任务上下文中（如进程执行器）返回 False。

聚合查询

summary = pool.get_cost_summary(child_ids)
print(summary)
# {
#   "task_count": 20, "tasks_with_cost": 18,
#   "tokens_in": 2400, "tokens_out": 960,
#   "api_calls": 20, "estimated_cost": 0.024, "currency": "USD"
# }

total = pool.get_cost_summary()   # task_ids=None 时聚合全部任务
字段说明
task_count参与聚合的任务数
tasks_with_cost至少有一条成本记录的任务数
tokens_in / tokens_out / api_calls明细累加值
estimated_cost金额累加值；浮点数，不适用于财务结算
currency唯一币种、空字符串或 MIXED

聚合在存储层完成，不需要把任务记录逐个读入进程。task_ids 中不存在的 ID 会被忽略，不会报错。

成本事件

async def on_cost(event):
    print(event.task_id, event.data)
    # {"tokens_in": 120, "tokens_out": 48, "api_calls": 1,
    #  "estimated_cost": 0.0012, "currency": "USD"}

pool.event_bus.subscribe("task.cost_reported", on_cost)

task.cost_reported 的负载是本次上报的明细，不是累计值。event.data 中只有本次传入的字段，未传 currency 时不含该键。该事件没有专用便捷方法，使用 event_bus.subscribe() 订阅。

边界

  • 费用完全由调用方提供，NeoTask 不解析模型价格，也不校验金额单位。
  • 重试与人工重试产生的成本都会保留并累加；任务最终失败也不影响已记录的消耗。
  • 终态清理删除任务时会一并删除成本明细，需要长期成本报表时应定期聚合后外部归档。
  • 事件可能因有界队列丢弃而缺失，成本汇总请以 get_cost_summary() 的存储结果为准。
