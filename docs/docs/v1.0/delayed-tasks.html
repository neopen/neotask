核心概念

延时与周期任务

延时、指定时间、固定间隔与 Cron 任务的提交、管理和错过策略。

v1.0 · NeoTask 1.0.x 更新于 2026-10-30 约 8 分钟 读完 GitHub

延时任务是“在某个时间点执行一次”，周期任务是“按间隔或 Cron 重复执行”。两者都由 TaskScheduler 提供，底层复用 TaskPool 的执行与存储。

延时一次

from datetime import datetime, timedelta
from neotask import TaskScheduler

scheduler = TaskScheduler(executor=send_reminder)

# 相对延迟
task_id = scheduler.submit_delayed({"user_id": 42}, delay_seconds=300)

# 指定时间
run_at = datetime.now() + timedelta(hours=2)
task_id = scheduler.submit_at({"user_id": 42}, execute_at=run_at)
参数默认值说明
delay_seconds必填延迟秒数；小于等于 0 时立即入队
task_id自动生成自定义 ID 需保证唯一
priorityNORMAL到期后按该优先级入队
ttl3600任务级超时 / 回收阈值

时间轮

SchedulerConfig(enable_time_wheel=True) 后，延时任务会先写入存储（状态 pending），再加入时间轮。到期时只把任务推入队列，因此等待期间仍可通过任务 ID 查询和取消。

from neotask import TaskScheduler, SchedulerConfig

config = SchedulerConfig.high_performance()  # 360 槽 × 1 秒
scheduler = TaskScheduler(executor=handle, config=config)
scheduler.start()
  • 默认量程为 slots × tick × max_rounds，即 60 × 1 秒 × 100 轮 ≈ 100 分钟。
  • 超过量程的延迟会退回普通延时队列，不会丢失。
  • 时间轮本身不持久化，进程重启后未到期的任务不会自动入队。

固定间隔

periodic_id = scheduler.submit_interval(
    {"job": "heartbeat"},
    interval_seconds=30,
    run_immediately=True,
    max_runs=None,
    name="service-heartbeat",
    missed_policy="skip",
)
参数默认值说明
interval_seconds必填两次执行的间隔
run_immediatelyTrue是否立即执行第一次
max_runsNone最大执行次数；None 表示不限
missed_policy"skip"错过执行的补偿策略

Cron

report_id = scheduler.submit_cron(
    {"job": "daily-report"},
    "0 9 * * *",          # 每天 09:00
    name="daily-report",
    max_runs=None,
    missed_policy="run_once",
)

Cron 表达式由 croniter 解析，支持标准五段格式。首次执行时间为下一个匹配时刻，不会立即执行。

missed_policy行为
skip跳过所有错过的槽位，从当前时间继续（默认）
ignore忽略错过的槽位，与 skip 类似
run_once错过后只补跑一次
catch_up补跑错过的槽位，单轮最多 5 次

管理周期任务

方法说明
get_periodic_tasks()列出全部周期任务
get_periodic_task(task_id)查询单个周期任务
pause_periodic(task_id)暂停，保留定义
resume_periodic(task_id)恢复并重新计算下次执行时间
cancel_periodic(task_id)删除周期任务

cancel(task_id) 会先尝试按周期任务取消，找不到时再按普通任务取消。

持久化

存储周期任务跨重启延时任务跨重启
memory否，注册时输出一次告警否
SQLite是，需 enable_persistence=True否，未到期任务不会自动入队
Redis是，需 enable_persistence=True否，未到期任务不会自动入队
重启边界：任务记录会保留，但延时堆与时间轮都在进程内存中。重启后，处于等待期的延时任务会停留在 pending，不会自动执行；需要业务侧在启动时扫描并重新提交，或改用周期任务表达重复调度。

关闭

scheduler.shutdown(graceful=True, timeout=30)

优雅关闭会先停止接收新任务，等待队列清空，再停止周期管理器与时间轮。
