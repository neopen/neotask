术语表

任务、队列、Worker、调度、重试、回收、死信等核心术语的统一解释。

v1.0 · NeoTask 1.x 更新于 2026-11-22 约 5 分钟 读完 GitHub

本页统一文档中反复出现的任务、队列、调度与可靠性术语。遇到陌生概念时先查这里，再进入对应章节。

术语英文 / 标识定义
任务Task一次待执行的计算，包含数据、状态、优先级、结果与时间戳
任务池TaskPool即时任务的公共入口，管理提交、队列、Worker 与结果
调度器TaskScheduler在任务池之上提供延时、指定时刻、固定间隔与 Cron 调度
执行器TaskExecutor / Executor真正执行任务的组件，分为异步、线程与进程三类
WorkerWorker并发取任务并调用执行器的工作单元
队列Queue按优先级组织的待执行任务集合，含容量上限
预取PrefetchWorker 提前批量取任务到本地，降低取任务开销
优先级Priority0–3 四级，数值越小越优先，同级 FIFO
生命周期Lifecycle任务从创建到终态的状态迁移与事件序列
终态Terminal statesuccess / failed / cancelled，不可再迁移
重试Retry执行异常后按线性延迟重新入队
超时Timeouttask_timeout 限制单次执行；ttl 限制任务生命周期
心跳HeartbeatRedis 模式下节点存活上报，用于失联判定
回收器ReclaimerRedis 模式下接管失联节点或超时任务的组件
死信Dead letter重试耗尽或回收失败的任务记录，Redis 模式提供
断点Checkpoint任务内部进度的持久化快照，用于续跑
父子任务Parent / child task通过 parent_task_id 建立关联，不自动汇总
BlackboardMemory context store仅 Memory 后端的进程内共享上下文
事件总线EventBus把生命周期事件异步投递给订阅者的组件
轻量快照Metrics snapshotget_metrics() 返回的计数与聚合视图，不加载任务实体

容易混淆的三组概念

对比区别
ttl vs task_timeoutttl 是任务生命周期与回收阈值；task_timeout 是单次执行的强制中断时长。只设一个都会留下盲区。
cancel() vs delete()取消移除队列项并置为 cancelled，不撤销已发生的副作用；删除只移除记录，不中断执行。
report_failure() vs 抛异常业务判定失败用 report_failure()，直接终结且不重试；执行异常走自动重试。
