任务关联与共享上下文

父子任务关联、外部指定 task_id 的唯一性语义，以及仅 memory 后端可用的 Blackboard。

v1.0 · NeoTask 1.x 更新于 2026-11-17 约 6 分钟 读完 GitHub

1.1 补齐了三类“任务之间”的能力：父子任务关联、外部指定 task_id，以及 memory 模式下的进程内共享上下文（Blackboard）。NeoTask 只负责记录、查询与保存，不做依赖编排、状态汇总或跨节点共享。

父子任务关联

提交时传入 parent_task_id，即可把子任务挂在父任务下。关联只写入任务记录，不校验父任务是否存在，也不会改变执行顺序或触发父任务等待。

parent_id = pool.submit({"batch": "2026-11"}, task_id="batch-2026-11")
child_ids = [
    pool.submit({"doc": doc}, parent_task_id=parent_id)
    for doc in documents
]
方法返回说明
get_children(task_id)List[str]按 parent_task_id 查询，创建时间升序；父任务不存在时返回空列表
get_parent(task_id)str | None任务不存在或没有父任务时返回 None
get_result(task_id)dict包含 parent_task_id
不做自动汇总：父任务按自己的执行器返回值结束，子任务的成功或失败不会改变父任务状态。get_children() 只返回 ID，需要汇总时由业务代码或上层编排服务（NeoFlow）调用 wait_all()、get_result() 自行判断。

submit_batch() 与 create_pending_task() 当前没有 parent_task_id 参数；需要父子关联时逐条调用 submit()。Redis 与 SQLite 会为父任务维护查询索引，单个父任务下大量子任务时仍建议分页消费。

外部指定 task_id

submit()、submit_async()、create_pending_task() 都接受调用方提供的 task_id，便于把业务主键映射到任务 ID。

pool.submit({"order_id": 42}, task_id="order-42")

# 同一 ID 已存在（包括已进入终态）时再次提交
pool.submit({"order_id": 42}, task_id="order-42")
# TaskAlreadyExistsError
  • 唯一性由存储层原子创建保证：多节点同时提交同一 ID 时只有一个成功，其余抛 TaskAlreadyExistsError。
  • 它只防止重复创建，不代表任务只执行一次；重试、回收和人工 retry() 仍会再次执行，业务需保持幂等。
  • 要重新执行已有 ID 的任务，调用 retry(task_id)；删除记录后可以重新创建，但该任务的 checkpoint 也会被删除。

Blackboard：进程内共享上下文

Blackboard 是每个 TaskPool 实例自带的键值空间，供同一进程内的任务读取共享状态，例如功能开关、临时凭证或批次元数据。仅 memory 存储后端提供。

pool.context_set("feature_flags", {"qa": True}, ttl=600)
flags = pool.context_get("feature_flags") or {}
pool.context_delete("feature_flags")
方法说明
context_set(key, value, ttl=None)写入或覆盖；ttl 为秒，None 表示不过期
context_get(key)读取；不存在或已过期返回 None
context_delete(key)删除；返回是否命中
  • 写入与读取都会深拷贝值，修改返回值不会影响已存内容。
  • TTL 采用惰性过期：读取时判定，写入时顺带清理过期键，不启动后台线程。
  • 上下文只存在当前进程内，不跨进程、不跨节点、不随任务持久化；进程退出即丢失。
  • storage_type 不是 memory 时调用这些方法会抛 UnsupportedFeatureError；多节点共享状态应使用外部存储。
  • TaskScheduler 的 context_* 委托给内部 TaskPool，作用域同样限于该调度器实例。
并发写入：Blackboard 只保证单键读写的线程安全，不提供跨键事务。多个任务同时“读-改-写”同一键时会互相覆盖，需要原子计数或状态机时应使用数据库或 Redis。
