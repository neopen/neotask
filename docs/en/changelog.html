Upgrade advice

Production should run the latest patch release. Since 1.0.2 dependencies are limited to a small set of base libraries; the current 1.2.1 baseline depends on aiosqlite, croniter and colorama, and supports Python 3.8+. Since 1.0.8, neotask --benchmark provides a lightweight performance self-check; 1.1 added checkpoint resume, cost tracking and business failure reporting; 1.2 adds monitoring snapshots and periodic push; 1.2.1 fixes prefetch idle backoff, in-memory batch writes and Redis batch reads.

pip install -U neotask

In the GitHub repository, choose Watch → Releases to be notified of every release.

v1.2.1Latest
2026-11-22 Patch

Full-path performance fixes: prefetch empty-queue backoff, in-memory queue batch write/remove, blocking monitoring samples, and Redis batch reads.

  • Prefetch workers no longer add exponential backoff on an empty queue; sparse latency drops from up to 500 ms to 12–26 ms
  • In-memory batch push becomes O(k log n); pushing 1,000 items into a 10,000-item queue takes 0.471 ms
  • Batch remove uses lazy tombstones; removing 1,000 items takes 0.668 ms without rebuilding the heap
  • psutil sampling moves to a thread pool, removing periodic ~100 ms event-loop stalls
  • Redis list_by_status uses one MGET; memory pagination and Blackboard TTL writes optimized
  • Regression: 538 unit tests passed / 12 skipped; 87 integration tests passed / 1 skipped

2026-11-20 Feature

Performance and lightweight monitoring: snapshots, periodic push, plus 1,000-task concurrency, checkpoint and progress benchmarks.

  • Added TaskPool.get_metrics() lightweight snapshot and on_metrics() periodic push
  • Added repository count and retry-count APIs so snapshots avoid loading task entities
  • Added 1,000-task concurrency, submit latency, and batch throughput benchmarks
  • Added checkpoint write cost and monitoring snapshot cost benchmarks
  • Added a benchmark for progress-report frequency impact on throughput
  • Unsubscribed events are no longer enqueued; internal handlers subscribe by event type
  • SQLite skips no-op commits in autocommit mode and prunes checkpoints only when over limit
