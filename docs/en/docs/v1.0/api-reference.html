API reference

Public TaskPool and TaskScheduler methods, 1.2 additions, parameter defaults, and return semantics.

v1.0 · NeoTask 1.x Updated 2026-11-22 12 min read GitHub

The public entry points are TaskPool and TaskScheduler. Unless noted otherwise, every synchronous method has an _async counterpart with the same parameters and return value. This documentation is based on 1.2.1; methods and events marked 1.1 and 1.2 are additions from those releases.

from neotask import TaskPool, TaskScheduler, TaskPoolConfig, SchedulerConfig

TaskPool

TaskPool(executor=None, config=None)

executor can be a plain function, a coroutine function or a TaskExecutor instance; when it is None, a default executor that returns a fixed result is used.

Lifecycle and submission

MethodDescription
start()Explicit start; the first submission also starts it automatically
shutdown(graceful=True, timeout=30)Stop accepting new tasks, wait for the queue to drain and then shut down
submit(data, task_id=None, priority=NORMAL, delay=0, ttl=3600, parent_task_id=None, resume_from_checkpoint=False)Submit a task and return its ID; resume_from_checkpoint requires an explicit task_id
submit_batch(tasks, priority=NORMAL, ttl=3600, partial_on_error=False)Submit a list of tasks one by one and return a list of IDs; parent/child parameters are not supported
create_pending_task(data, task_id=None, priority=NORMAL, ttl=3600, resume_from_checkpoint=False)Create the record only; do not enqueue it
enqueue_task(task_id)Enqueue a pending task; returns False for states other than pending

Waiting and queries

MethodDescription
wait_for_result(task_id, timeout=300)Wait for and return the result; raises on failure, cancellation or timeout
wait_all(task_ids, timeout=300)Wait for each task in turn and return {task_id: result}
get_status(task_id)Status string, or None
get_result(task_id)Result summary dictionary, or None
get_task(task_id)Full task dictionary, or None
task_exists(task_id)Whether the task exists

Task management

MethodDescription
cancel(task_id)Remove the queue entry and set the task to cancelled; valid for pending / running only
retry(task_id, delay=0)Reset a terminal task and enqueue it again
delete(task_id)Delete the task record
cleanup_terminal_tasks() / cleanup_terminal_tasks_async()Clean up terminal tasks past their retention period immediately; returns the number deleted
pause() / resume()Pause / resume dequeueing; submissions are still accepted
clear_queue()Clear the queue; existing task records are not modified

Checkpoint resume (1.1)

MethodDescription
save_checkpoint(task_id, state)Save a full state snapshot and return the new version number; returns 0 if the task does not exist or checkpointing is disabled
load_checkpoint(task_id)Read the latest checkpoint; returns None if none exists or checkpointing is disabled

Inside executors use the module-level functions: await save_checkpoint(state) / await load_checkpoint() for async tasks, and save_checkpoint_sync() / load_checkpoint_sync() for threaded tasks; with a process executor, the parent process calls the methods above. See Checkpoint resume.

Cost, failure and relations (1.1)

MethodDescription
get_children(task_id)Return child task IDs for a parent_task_id, ascending by creation time
get_parent(task_id)Return the parent task ID, or None when there is none
report_failure(task_id, reason, detail="")Terminate a task from outside when a business rule fails; applies to running tasks only and does not enter automatic retry
report_cost(task_id, tokens_in=0, tokens_out=0, api_calls=0, estimated_cost=None, currency=None)Accumulate task cost; terminal tasks can also be updated
get_cost_summary(task_ids=None)Aggregate cost and return task count, tokens, API calls, amount and currency; None means all tasks

Inside executors use report_failure(reason, detail) and report_cost(...); both are synchronous functions. See Failure recovery and Cost and duration.

Blackboard (1.1, memory only)

MethodDescription
context_set(key, value, ttl=None)Write to the in-process shared context; ttl is in seconds and None means no expiry
context_get(key)Read a value; returns None if it is missing or expired
context_delete(key)Delete a key; returns whether it was present

Calling these on a non-memory backend raises UnsupportedFeatureError. The scope is the current TaskPool instance; values do not cross processes and are not persisted. See Task relations and shared context.

Statistics and health

MethodDescription
get_stats()Queue, task counters, metrics, reclamation and prefetch summary
get_metrics()1.2 lightweight monitoring snapshot: counters, queue depth by priority, age of the oldest pending task, retry queue, storage health and checkpoint count, without loading task entities
on_metrics(handler, interval=60)1.2 periodic push of get_metrics() snapshots; returns an unsubscribe function
get_worker_stats()Busy state and counters for each worker
get_health_status()Storage, queue and system health checks; cached for 5 seconds
get_queue_size()Total of the priority queue and the delayed queue

get_metrics() reads counters and aggregate queries only and suits probes and high-frequency reporting; when you need full task detail, use get_stats() or get_task() instead. See Monitoring and health checks.

Locks and nodes

MethodDescription
acquire_lock(task_id, ttl=30)Acquire the task:{task_id} lock
release_lock(task_id)Release a lock held by this instance
get_active_nodes()List of active nodes in Redis mode
is_leader()Always returns False

Events

Method / attributeDescription
event_busRead-only property returning the internal EventBus; call get_stats() to inspect the queue and drop counters
on_created(handler)task.created
on_started(handler)task.started
on_completed(handler)task.completed
on_failed(handler)task.failed
on_cancelled(handler)task.cancelled
on_progress(handler)task.progress
on_reclaimed(handler)task.reclaimed
event_bus.subscribe("task.checkpointed", handler)task.checkpointed (1.1); data is {"version": n}
event_bus.subscribe("task.cost_reported", handler)task.cost_reported (1.1); data holds the details of this report

The two events added in 1.1 have no on_* convenience methods; subscribe to them through event_bus.subscribe() only.

TaskScheduler

TaskScheduler(executor=None, config=None)

It creates a TaskPool internally and adds delayed, periodic and Cron scheduling. Apart from sync-only items such as get_periodic_*, the methods below also have _async versions.

Delayed tasks

MethodDescription
submit_delayed(data, delay_seconds, task_id=None, priority=NORMAL, ttl=3600)Run once after a delay
submit_at(data, execute_at, task_id=None, priority=NORMAL, ttl=3600)Run once at a specified time

Periodic tasks

MethodDescription
submit_interval(data, interval_seconds, task_id=None, priority=NORMAL, run_immediately=True, max_runs=None, name="", missed_policy=None)Run at a fixed interval
submit_cron(data, cron_expr, task_id=None, priority=NORMAL, max_runs=None, name="", missed_policy=None)Run according to a Cron expression
get_periodic_tasks()List periodic tasks
get_periodic_task(task_id)Query a single periodic task
pause_periodic(task_id)Pause a periodic task
resume_periodic(task_id)Resume a periodic task
cancel_periodic(task_id)Delete a periodic task

Methods delegated to TaskPool

MethodDescription
submit(...) / submit_async(...)Same as TaskPool
wait_for_result(...)Same as TaskPool

cancel / delete / retryTries the periodic task first, then operates on regular tasks
get_stats / get_queue_size / get_health_statusIncludes periodic and timing-wheel statistics
event_busReturns the EventBus of the internal TaskPool
pause / resume / clear_queueSame as TaskPool
get_children / get_parentSame as TaskPool

Exceptions

ExceptionTrigger
TaskSchedulerErrorBase class for all exceptions
TaskNotFoundErrorWaiting for a task that does not exist
TaskAlreadyExistsErrorSubmitting with an existing task_id, including tasks already in a terminal state
QueueFullErrorThe queue reached queue_max_size
BatchSubmitErrorA batch submission contains a failing item and was rolled back; read index and cause to locate it
TimeoutErrorwait_for_result timed out
UnsupportedFeatureErrorThe current storage backend does not support the capability, for example calling Blackboard on a non-memory backend
TaskErrorDefined but unused in the current version

CLI and lightweight benchmarks

Since 1.0.8 the installed package provides a neotask entry point, equivalent to python -m neotask:

neotask --version
neotask --help
neotask --benchmark --tasks 2000 --concurrency 10 --json
OptionDescription
--executor MODULE:FUNCExecutor; also accepts a file path form such as ./bench.py:func
--tasks / --concurrencyTask count and worker concurrency, 200 / 10 by default
--warmup / --timeoutNumber of warmup tasks and the wait timeout
--payloadJSON task data template, {"index": i} by default
--no-prefetchDisable worker prefetch
--jsonEmit JSON for CI or scripts to consume

From code, call run_benchmark() / run_benchmark_async(), which return a BenchmarkResult; benchmarks disable health checks, metrics and reporters by default.

Other exports

neotask also exports executor, storage, queue, lock, monitoring and distributed components: AsyncExecutor, ThreadExecutor, ProcessExecutor, MemoryTaskRepository, SQLiteTaskRepository, RedisTaskRepository, MemoryCheckpointRepository, SQLiteCheckpointRepository, RedisCheckpointRepository, PriorityQueue, DelayedQueue, MemoryLock, RedisLock, WatchDog, MetricsCollector, HealthChecker, NodeManager, Coordinator and more.

The executor-scoped functions added in 1.1, report_failure, report_cost, save_checkpoint, load_checkpoint, and the synchronous variants save_checkpoint_sync and load_checkpoint_sync, are exported directly as well. See neotask.__all__ for the complete list.
