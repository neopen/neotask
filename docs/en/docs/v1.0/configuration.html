Configuration reference

TaskPoolConfig and SchedulerConfig fields, defaults, scope, and common presets.

v1.0 · NeoTask 1.x Updated 2026-11-22 10 min read GitHub

NeoTask configuration is provided by two dataclasses: TaskPoolConfig for immediate tasks and SchedulerConfig for delayed and periodic tasks. Every field has a default, so a direct instantiation is enough to run.

from neotask import TaskPool, TaskPoolConfig

config = TaskPoolConfig(
    storage_type="redis",
    redis_url="redis://127.0.0.1:6379/0",
    lock_type="redis",       # must be set explicitly when built by hand; the redis() factory sets it automatically
    worker_concurrency=20,
    task_timeout=60,
    max_retries=3,
)
pool = TaskPool(executor=handle, config=config)

TaskPoolConfig

FieldDefaultNotes
storage_type"memory"memory / sqlite / redis
sqlite_path"/data/neotask.db"SQLite database path
redis_urlNoneRedis connection string; required when using Redis
executor_typeExecutorType.ASYNCTakes effect only when an asynchronous executor is passed
max_workers10Thread/process count inside the executor, depending on the executor implementation
worker_concurrency10Number of tasks executed concurrently
prefetch_size20Tasks prefetched per batch; also determines the local queue capacity (5 times)
task_timeoutNoneSingle-task execution timeout in seconds; unlimited by default
queue_max_size10000Queue limit; submission raises QueueFullError when full
priority_levels4Number of priority levels; the current implementation is fixed at four
event_queue_max_sizeNonePending event queue limit; None means unbounded
event_overflow_policy"drop"Policy when the queue is full; currently only dropping new events is supported
event_slow_handler_threshold1.0Count and warn when a single event callback exceeds this many seconds
lock_type"memory"memory / redis; TaskPoolConfig.redis() sets it to redis automatically
lock_timeout30Task lock TTL in seconds
enable_metricsTrueCollect task metrics
enable_health_checkTrueEnable storage, queue and system health checks
enable_reporterFalsePrint a console metrics summary every 60 seconds
max_retries3Automatic retries after a failure
retry_delay1.0Retry delay base; the delay of the n-th retry is retry_delay × n
enable_checkpointTrueEnable checkpoint resume; when off no checkpoint repository is created and the related APIs return 0 / False
checkpoint_keep_versions5Checkpoint versions kept per task; 0 means keep none
enable_prefetchTrueEnable batch prefetch
prefetch_min_threshold5Not effective in the current version; the threshold is derived from prefetch_size
enable_terminal_cleanupTruePeriodically clean up succeeded, failed and cancelled terminal tasks
terminal_cleanup_interval60.0Terminal cleanup scan interval in seconds; not started when ≤ 0
terminal_retention_seconds0Terminal retention period; 0 means use the task's own ttl
enable_reclaimerTrueEnable the task reclaimer in Redis mode; not created when off
enable_heartbeatTrueEnable the node heartbeat in Redis mode; not created when off
drain_delayed_on_shutdownFalseOn shutdown, move delayed tasks that are not yet due into the priority queue immediately and wait for execution
reclaimer_interval30.0Reclaimer scan interval in Redis mode in seconds
heartbeat_interval5Heartbeat interval in Redis mode in seconds
heartbeat_timeout20Node heartbeat timeout in seconds
enable_dead_letterTrueEnable the dead letter queue in Redis mode
dead_letter_max_size10000Dead letter queue capacity
dead_letter_ttl604800Dead letter retention time in seconds (7 days by default)
node_idHostnameNode identifier; must be unique in a distributed deployment
The switches take effect since 1.0.8: enable_reclaimer and enable_heartbeat now directly decide whether the reclaimer and heartbeat components are created, and they only apply when storage_type="redis" and redis_url is configured. Turning off the heartbeat also loses the node liveness view, and orphan reclamation is skipped.

SchedulerConfig

FieldDefaultNotes
storage_type"memory"Shared with the underlying TaskPool
sqlite_path / redis_urlSame as TaskPoolConfigStorage connection parameters
worker_concurrency10Number of tasks executed concurrently
max_retries / retry_delay3 / 1.0Failure retry policy
enable_checkpoint / checkpoint_keep_versionsTrue / 5Checkpoint switch and version retention count, passed to the internal TaskPool
event_queue_max_size / event_overflow_policyNone / "drop"Same as TaskPoolConfig, passed to the internal TaskPool
event_slow_handler_threshold1.0Slow event callback warning threshold in seconds
enable_persistenceTruePeriodic tasks are written to SQLite / Redis and can be recovered after a restart
scan_interval1.0Scheduling loop scan interval in seconds
enable_periodic_managerTrueWhen off, degrades to a simple in-memory periodic scheduler
enable_time_wheelFalseEnable the time wheel for delayed tasks
time_wheel_slots60Number of time wheel slots
time_wheel_tick1.0Time wheel tick interval in seconds
default_max_runsNoneDefault maximum runs for periodic tasks
default_missed_policy"skip"Default policy for missed executions
Configuration is only passed down in part: TaskScheduler passes storage, worker_concurrency, retries, checkpoint, progress write-back, cache limits, shutdown delay handling and event bus fields to the internal TaskPool, and sets the lock type according to the storage type. Prefetch, monitoring, task_timeout, queue capacity, dead letter and other parameters still require constructing TaskPool directly or modifying the underlying config; SchedulerConfig does not expose these fields today.

Common presets

ScenarioConfiguration
Local developmentTaskPoolConfig.memory()
Single-machine persistenceTaskPoolConfig.sqlite("/var/lib/neotask.db"); writes are already serialized, but a single writer is still recommended
Shared queue across nodesTaskPoolConfig.redis("redis://host:6379/0", node_id="worker-1")
Scheduled tasksSchedulerConfig.redis("redis://host:6379/0") or SchedulerConfig.sqlite(path)
Low-latency delayed tasksSchedulerConfig.high_performance() (time wheel enabled)

Environment variables

This version does not read environment variables; all configuration is passed in code. In containerized deployments, construct the configuration object explicitly in your startup script.
