Glossary

Shared definitions for task, queue, worker, scheduler, retry, reclaim, dead letter, and more.

v1.0 · NeoTask 1.x Updated 2026-11-22 5 min read GitHub

This page collects the task, queue, scheduling and reliability terms used across the docs. Look here first when a concept is unfamiliar, then follow the link to its chapter.

TermIdentifierDefinition
TaskTaskA unit of work with data, status, priority, result and timestamps
Task poolTaskPoolPublic entry point for immediate tasks: submission, queue, workers and results
SchedulerTaskSchedulerAdds delayed, submit-at, fixed-interval and Cron scheduling on top of the pool
ExecutorTaskExecutor / ExecutorThe component that runs tasks: async, thread or process
WorkerWorkerConcurrent unit that pulls tasks and invokes the executor
QueueQueuePriority-ordered set of pending tasks with a capacity limit
PrefetchPrefetchWorkers fetch tasks in batches ahead of time to cut dequeue overhead
PriorityPriorityFour levels 0–3, lower is more urgent, FIFO within a level
LifecycleLifecycleState transitions and events from creation to a terminal state
Terminal stateTerminal statesuccess / failed / cancelled; no further transitions
RetryRetryRe-enqueue after an execution error with a linear delay
TimeoutTimeouttask_timeout bounds one execution; ttl bounds the task lifetime
HeartbeatHeartbeatRedis-mode node liveness report used for failure detection
ReclaimerReclaimerRedis-mode component that adopts tasks from lost nodes or expired runs
Dead letterDead letterRecords of tasks that exhausted retries or failed reclaim; Redis mode only
CheckpointCheckpointPersisted snapshot of in-task progress used to resume
Parent / child taskParent / child taskLinked through parent_task_id; not aggregated automatically
BlackboardMemory context storeIn-process shared context available on the Memory backend only
Event busEventBusDelivers lifecycle events to subscribers asynchronously
Metrics snapshotMetrics snapshotCounters and aggregates returned by get_metrics() without loading task entities

Three easy-to-confuse pairs

PairDifference
ttl vs task_timeoutttl is the task lifetime and reclaim threshold; task_timeout forcibly interrupts a single execution. Setting only one leaves a blind spot.
cancel() vs delete()Cancel removes the queue entry and marks the task cancelled but does not undo side effects; delete only removes the record and does not interrupt a running task.
report_failure() vs raisingUse report_failure() when business logic rejects the result: the task is terminated without retry. Execution errors go through automatic retry.
