Quickstart

Install NeoTask 1.2.1, submit your first task, and choose sync, async, or context manager usage.

v1.0 · NeoTask 1.x Updated 2026-11-22 7 min read GitHub

NeoTask 1.x provides two entry points: TaskPool handles immediate tasks, and TaskScheduler handles delayed and periodic scheduling. Both use the same execution model: you provide a callable, and NeoTask handles queueing, concurrent execution, state recording and result delivery.

Requirements

ItemRequirement
Python≥ 3.8
Core dependenciesaiosqlite, croniter, colorama
Redis backendpip install "neotask[redis]"
System metricspip install "neotask[monitor]"
 
pip install neotask

Verify the installation

python -c "import neotask; print(neotask.__version__)"
# 1.2.1

neotask --version
# neotask 1.2.1

If the import fails, first confirm that the current Python environment matches the install location. The Redis backend and system metrics are optional dependencies; when they are missing, the memory mode still runs. Since 1.0.8 the package ships a neotask CLI entry point for version queries and lightweight benchmarks; see Benchmarks for the full benchmarks and the API details.

Since 1.1 NeoTask also provides checkpoint resume, business failure reporting, cost collection and parent/child task links; 1.2 adds the lightweight get_metrics() monitoring snapshot and periodic on_metrics() push. When you need these capabilities, start with Checkpoints or Monitoring and health checks.

Lightweight benchmark

# Built-in 5 ms executor, 200 tasks, 10 concurrent
neotask --benchmark

# Use your own executor and output JSON
neotask --benchmark --executor my_tasks:handle --tasks 2000 --json

The benchmark entry point disables health checks, metrics and the reporter by default and measures only submission, completion and end-to-end latency. It is suitable for validating the environment and the executor, not as a substitute for a full load test.

Submit your first task

The executor receives a dict, and its return value is stored as the task result. The return value must be JSON-serializable.

import asyncio
from neotask import TaskPool

async def handle(data):
    await asyncio.sleep(0.1)
    return {"value": data["value"] * 2}

pool = TaskPool(executor=handle)
task_id = pool.submit({"value": 21})
result = pool.wait_for_result(task_id)
print(result)  # {'value': 42}
pool.shutdown()

TaskPool starts automatically on the first submit; you can also call pool.start() explicitly.

Three calling styles

StyleWhen to useExample
Synchronous APIScripts, plain functions, needing the result immediatelysubmit() + wait_for_result()
Asynchronous APIServices already inside an event loopawait submit_async() + await wait_for_result_async()
Context managerNeed guaranteed resource cleanupwith TaskPool(...) as pool:
 
# Asynchronous
task_id = await pool.submit_async({"value": 1})
result = await pool.wait_for_result_async(task_id, timeout=30)

# Synchronous context manager
with TaskPool(executor=handle) as pool:
    task_id = pool.submit({"value": 2})
    print(pool.wait_for_result(task_id))

# Asynchronous context manager
async with TaskPool(executor=handle) as pool:
    task_id = await pool.submit_async({"value": 3})
    print(await pool.wait_for_result_async(task_id))

Submit without waiting

Background tasks usually do not need the result. After submitting, query the state or result by task ID:

task_id = pool.submit({"value": 5})
pool.get_status(task_id)   # pending / running / success / failed / cancelled
pool.get_result(task_id)   # contains status, result, error and timestamps

# Blocking wait when needed
result = pool.wait_for_result(task_id, timeout=60)

Batch submission

task_ids = pool.submit_batch([{"value": i} for i in range(100)])
results = pool.wait_all(task_ids, timeout=60)
# {task_id: result}; the value of a failed task looks like {"error": "..."}

Common errors

SymptomCommon causeWhat to do
ModuleNotFoundError: neotaskInstalled into another Python or virtual environmentConfirm that python -m pip matches the running interpreter, then reinstall
Redis connection failureThe redis extra is not installed or the address is unreachableInstall neotask[redis] and check redis_url and the network
Task stays pendingThe pool is not started, concurrency is 0 or a worker failedCall pool.start() explicitly and use get_stats() to inspect the queue and worker state
wait_for_result times outThe task is still running, or a blocking synchronous function holds the event loopIncrease the wait time; move blocking code to ThreadExecutor
database is lockedSeveral processes share the same SQLite file1.0.8 serializes writes within a single process; across processes still prefer a single writer, or switch to Redis
