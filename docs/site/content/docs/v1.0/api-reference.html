公开入口为 TaskPool 与 TaskScheduler。除特别标注外，每个同步方法都有一个同名的 _async 版本，参数与返回值一致。当前文档基线为 1.2.1，标注“1.1”与“1.2”的方法与事件为新增能力。

from neotask import TaskPool, TaskScheduler, TaskPoolConfig, SchedulerConfig

TaskPool

TaskPool(executor=None, config=None)

executor 可以是普通函数、协程函数或 TaskExecutor 实例；为 None 时使用返回固定结果的默认执行器。

生命周期与提交

方法说明
start()显式启动；首次提交也会自动启动
shutdown(graceful=True, timeout=30)停止接收新任务，等待队列清空后关闭
submit(data, task_id=None, priority=NORMAL, delay=0, ttl=3600, parent_task_id=None, resume_from_checkpoint=False)提交任务，返回任务 ID；resume_from_checkpoint 需配合显式 task_id
submit_batch(tasks, priority=NORMAL, ttl=3600, partial_on_error=False)逐条提交任务列表，返回 ID 列表；不支持父子关联参数
create_pending_task(data, task_id=None, priority=NORMAL, ttl=3600, resume_from_checkpoint=False)只创建记录，不入队
enqueue_task(task_id)把 pending 任务入队；非 pending 返回 False

等待与查询

方法说明
wait_for_result(task_id, timeout=300)等待并返回结果；失败、取消或超时抛异常
wait_all(task_ids, timeout=300)逐项等待，返回 {task_id: result}
get_status(task_id)状态字符串或 None
get_result(task_id)结果摘要字典或 None
get_task(task_id)完整任务字典或 None
task_exists(task_id)任务是否存在

任务管理

方法说明
cancel(task_id)移除队列项并置为 cancelled；仅 pending / running 有效
retry(task_id, delay=0)重置终态任务并重新入队
delete(task_id)删除任务记录
cleanup_terminal_tasks() / cleanup_terminal_tasks_async()立即清理已过保留期的终态任务，返回删除数量
pause() / resume()暂停 / 恢复出队，仍可继续入队
clear_queue()清空队列；不修改已创建的任务记录

断点续跑（1.1）

方法说明
save_checkpoint(task_id, state)保存完整状态快照，返回新版本号；任务不存在或未启用时返回 0
load_checkpoint(task_id)读取最近一次 checkpoint；没有或未启用时返回 None

执行器内部使用模块级函数：异步任务用 await save_checkpoint(state) / await load_checkpoint()，线程任务用 save_checkpoint_sync() / load_checkpoint_sync()；进程执行器由父进程调用上表方法。详见 断点续跑。

成本、失败与关联（1.1）

方法说明
get_children(task_id)按 parent_task_id 返回子任务 ID 列表，创建时间升序
get_parent(task_id)返回父任务 ID，没有时返回 None
report_failure(task_id, reason, detail="")外部终结业务失败任务；仅 running 状态生效，不进入自动重试
report_cost(task_id, tokens_in=0, tokens_out=0, api_calls=0, estimated_cost=None, currency=None)累加任务成本；终态任务也可追加
get_cost_summary(task_ids=None)聚合成本，返回任务数、token、API 次数、金额与币种；None 表示全部任务

执行器内部使用 report_failure(reason, detail) 与 report_cost(...)，两者都是同步函数。详见 故障恢复 与 成本与耗时。

Blackboard（1.1，仅 memory）

方法说明
context_set(key, value, ttl=None)写入进程内共享上下文；ttl 为秒，None 表示不过期
context_get(key)读取；不存在或过期返回 None
context_delete(key)删除；返回是否命中

非 memory 后端调用时抛 UnsupportedFeatureError。作用域为当前 TaskPool 实例，不跨进程、不持久化。详见 任务关联与共享上下文。

统计与健康

方法说明
get_stats()队列、任务计数、指标、回收与预取摘要
get_metrics()1.2 轻量监控快照：计数、各优先级队列深度、最老待处理任务年龄、重试队列、存储健康与断点数量，不加载任务实体
on_metrics(handler, interval=60)1.2 周期推送 get_metrics() 快照；返回取消订阅的函数
get_worker_stats()各 Worker 的忙碌状态与计数
get_health_status()存储、队列、系统健康检查；缓存 5 秒
get_queue_size()优先队列与延时队列总数

get_metrics() 只读取计数与聚合查询，适合探针与高频上报；需要完整任务明细时仍使用 get_stats() 或 get_task()。详见 监控与健康检查。

锁与节点

方法说明
acquire_lock(task_id, ttl=30)获取 task:{task_id} 锁
release_lock(task_id)释放本实例持有的锁
get_active_nodes()Redis 模式下的活跃节点列表
is_leader()始终返回 False

事件

方法 / 属性说明

周期任务

异常

异常触发场景
TaskSchedulerError所有异常的基类
TaskNotFoundError等待不存在的任务
TaskAlreadyExistsError使用已存在的 task_id 提交，包括任务已进入终态
QueueFullError队列达到 queue_max_size
BatchSubmitError批量提交中存在失败项且已回滚；读取 index 与 cause 定位失败项
TimeoutErrorwait_for_result 超时
UnsupportedFeatureError当前存储后端不支持该能力，例如非 memory 后端调用 Blackboard
TaskError已定义但当前版本未使用

命令行与轻量基准

1.0.8 起安装包提供 neotask 入口，等价于 python -m neotask：

neotask --version
neotask --help
neotask --benchmark --tasks 2000 --concurrency 10 --json
参数说明
--executor MODULE:FUNC执行器，也支持 ./bench.py:func 文件路径形式
--tasks / --concurrency任务数与 Worker 并发，默认 200 / 10
--warmup / --timeout预热任务数与等待超时
--payloadJSON 任务数据模板，默认 {"index": i}
--no-prefetch关闭 Worker 预取
--json输出 JSON，便于 CI 或脚本消费

代码内可调用 run_benchmark() / run_benchmark_async()，返回 BenchmarkResult；基准默认关闭健康检查、指标与 Reporter。

其他导出

neotask 还导出执行器、存储、队列、锁、监控与分布式组件：AsyncExecutor、ThreadExecutor、ProcessExecutor、MemoryTaskRepository、SQLiteTaskRepository、RedisTaskRepository、MemoryCheckpointRepository、SQLiteCheckpointRepository、RedisCheckpointRepository、PriorityQueue、DelayedQueue、MemoryLock、RedisLock、WatchDog、MetricsCollector、HealthChecker、NodeManager、Coordinator 等。
