NeoTask 采用 Facade 结构：对外只有 TaskPool 与 TaskScheduler，内部按职责拆分为分发、队列、执行、生命周期、事件与存储组件。所有节点对等，不依赖调度中心。

组件关系

TaskPool / TaskScheduler
        │
        ├── TaskDispatcher ──────► QueueScheduler
        │                              ├── PriorityQueue（4 级）
        │                              └── DelayedQueue（最小堆）
        │
        ├── WorkerPool ──────────► Executor（async / thread / process / class）
        │      ├── Prefetcher
        │      └── Supervisor
        │
        ├── TaskLifecycleManager ─► TaskRepository / QueueRepository
        ├── EventBus ─────────────► on_created / started / completed / failed /
        │                            cancelled / progress / reclaimed
        ├── LockManager ──────────► MemoryLock / RedisLock + WatchDog
        │
        └── Redis 模式附加组件
               ├── NodeManager
               ├── HeartbeatManager
               ├── TaskReclaimer
               ├── DeadLetterQueue
               └── Coordinator
组件职责
TaskDispatcher创建任务记录并写入优先队列或延时队列
QueueScheduler统一入队、出队、暂停、清空；延时到期后提升到优先队列
WorkerPool按 worker_concurrency 消费任务，执行超时与失败重试
TaskLifecycleManager维护状态机、结果、进度与等待者通知
TaskRepository任务记录持久化；Memory / SQLite / Redis 三种实现
EventBus异步事件分发，供回调和指标采集订阅
TaskReclaimer仅 Redis 模式：回收超时、孤儿任务与僵尸锁

任务执行路径

  1. 调用 submit() 或 submit_async()，TaskDispatcher 创建 PENDING 任务并写入存储。
  2. QueueScheduler 将任务放入优先队列；delay > 0 时先进入延时队列。
  3. WorkerPool 出队并将任务置为 RUNNING，获取任务锁后调用执行器。
  4. 执行完成写入 SUCCESS / FAILED，发布事件并唤醒 wait_for_result()。
  5. 失败且未超过 max_retries 时重置为 PENDING，按线性延迟重新入队。

三种部署形态

形态存储适用场景限制
单进程嵌入memory脚本、测试、短生命周期服务进程退出即丢失
单机持久化SQLite低频、单写入者、需要本地持久化多 worker 并发写入会出现 database is locked
多节点对等Redis水平扩展、共享队列、故障回收需要 Redis，且节点 ID 必须唯一

去中心化边界

Redis 模式下所有节点消费同一个队列，没有主节点、选主或任务指派。节点通过心跳登记存活状态，任务由任意空闲节点抢占执行。因此：

  • TaskPool.is_leader() 固定返回 False；
  • 任务不保证在提交节点执行；
  • 节点宕机后，其 RUNNING 任务由其他节点的回收器接手；
  • 执行顺序只保证队列的出队顺序，不保证跨节点的完成顺序。

执行器选择

执行器实现说明
AsyncExecutor直接 await默认；同步函数会被包装为异步调用，仍运行在事件循环线程
ThreadExecutor线程池适合阻塞 IO；支持 report_progress_sync()
ProcessExecutor进程池适合 CPU 密集任务；不支持进度上报
ClassExecutor调用对象 execute()适合带状态的服务对象
