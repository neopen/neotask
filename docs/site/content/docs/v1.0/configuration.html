NeoTask 的配置由两个数据类提供：TaskPoolConfig（即时任务）与 SchedulerConfig（延时与周期任务）。所有字段都有默认值，直接实例化即可运行。

from neotask import TaskPool, TaskPoolConfig

config = TaskPoolConfig(
    storage_type="redis",
    redis_url="redis://127.0.0.1:6379/0",
    lock_type="redis",       # 手工构造时必须显式设置；redis() 工厂会自动设置
    worker_concurrency=20,
    task_timeout=60,
    max_retries=3,
)
pool = TaskPool(executor=handle, config=config)

TaskPoolConfig

字段默认值说明
storage_type"memory"memory / sqlite / redis
sqlite_path"/data/neotask.db"SQLite 数据库路径
redis_urlNoneRedis 连接串；使用 Redis 时必填
executor_typeExecutorType.ASYNC仅在传入异步执行器时生效
max_workers10执行器内部线程/进程数，取决于执行器实现
worker_concurrency10同时执行的任务数
prefetch_size20每次预取任务数；同时决定本地队列容量（5 倍）
task_timeoutNone单任务执行超时（秒），默认不限制
queue_max_size10000队列上限，满时提交抛出 QueueFullError
priority_levels4优先级级数，当前实现固定为四级
event_queue_max_sizeNone待处理事件队列上限；None 表示无界
event_overflow_policy"drop"队列满时的策略；当前仅支持丢弃新事件
event_slow_handler_threshold1.0单个事件回调超过该秒数时计数并告警
lock_type"memory"memory / redis；TaskPoolConfig.redis() 会自动设为 redis
lock_timeout30任务锁 TTL（秒）
enable_metricsTrue采集任务指标
enable_health_checkTrue启用存储、队列、系统健康检查
enable_reporterFalse每 60 秒输出一次控制台指标摘要
max_retries3失败后的自动重试次数
retry_delay1.0重试延迟基数；第 n 次重试延迟为 retry_delay × n
enable_prefetchTrue启用批量预取
prefetch_min_threshold5当前版本未生效，阈值由 prefetch_size 推导
enable_terminal_cleanupTrue周期清理成功、失败与取消的终态任务
terminal_cleanup_interval60.0终态清理扫描间隔（秒）；≤ 0 时不启动
terminal_retention_seconds0终态保留时长；0 表示使用任务自身 ttl
enable_reclaimerTrueRedis 模式下启用任务回收器；关闭后不创建
enable_heartbeatTrueRedis 模式下启用节点心跳；关闭后不创建
drain_delayed_on_shutdownFalse停机时把未到期延时任务立即转入优先队列并等待执行
reclaimer_interval30.0Redis 模式下回收器扫描间隔（秒）
heartbeat_interval5Redis 模式下心跳间隔（秒）
heartbeat_timeout20节点心跳超时（秒）
enable_dead_letterTrueRedis 模式下启用死信队列
dead_letter_max_size10000死信队列容量
dead_letter_ttl604800死信保留时间（秒，默认 7 天）
node_id主机名节点标识；分布式部署时必须唯一
开关在 1.0.8 起生效：enable_reclaimer 与 enable_heartbeat 现在会直接决定是否创建回收器与心跳组件，仅在 storage_type="redis" 且配置了 redis_url 时有效。关闭心跳会同时失去节点存活视图，孤儿回收将被跳过。

SchedulerConfig

字段默认值说明
storage_type"memory"与底层 TaskPool 共用
sqlite_path / redis_url同 TaskPoolConfig存储连接参数
worker_concurrency10同时执行的任务数
max_retries / retry_delay3 / 1.0失败重试策略
event_queue_max_size / event_overflow_policyNone / "drop"与 TaskPoolConfig 相同，传入内部 TaskPool
event_slow_handler_threshold1.0慢事件回调告警阈值（秒）
enable_persistenceTrue周期任务写入 SQLite / Redis，重启后可恢复
scan_interval1.0调度循环扫描间隔（秒）
enable_periodic_managerTrue关闭后退化为内存中的简易周期调度
enable_time_wheelFalse启用时间轮处理延时任务
time_wheel_slots60时间轮槽位数
time_wheel_tick1.0时间轮滴答间隔（秒）
default_max_runsNone周期任务默认最大执行次数
default_missed_policy"skip"错过执行的默认策略
配置只部分向下传递：TaskScheduler 会把存储、worker_concurrency、重试、进度写回、缓存上限、停机延时处理与事件总线字段传给内部 TaskPool，并根据存储类型设置锁类型。预取、监控、task_timeout、队列容量、死信等参数仍需直接构造 TaskPool 或修改底层配置；SchedulerConfig 当前没有暴露这些字段。

常用档位

场景配置
本地开发TaskPoolConfig.memory()
单机持久化TaskPoolConfig.sqlite("/var/lib/neotask.db")；写入已串行化，仍建议单写入者
多节点共享队列TaskPoolConfig.redis("redis://host:6379/0", node_id="worker-1")
定时任务SchedulerConfig.redis("redis://host:6379/0") 或 SchedulerConfig.sqlite(path)
低延迟延时任务SchedulerConfig.high_performance()（启用时间轮）

环境变量

该版本不读取环境变量，所有配置均通过代码传入。容器化部署时请在启动脚本中显式构造配置对象。
