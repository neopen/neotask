NeoTask 是嵌入式库，不是独立服务：部署 NeoTask 意味着部署你的应用进程，并按需选择存储后端。本文给出本地、容器与生产环境的推荐形态，以及存储、网络、安全与升级要点。

本地部署

单机脚本或桌面工具直接使用 Memory 或 SQLite，无需额外进程：

pip install neotask

# 验证
python -c "import neotask; print(neotask.__version__)"
from neotask import TaskPool, TaskPoolConfig

pool = TaskPool(
    executor=handle,
    config=TaskPoolConfig.sqlite("/var/lib/myapp/neotask.db"),
)
  • 开发阶段用 TaskPoolConfig.memory()，重启即清空，便于复现。
  • 需要跨重启保留任务时用 SQLite，并确保目录存在且运行用户可写。
  • 定时任务使用 SchedulerConfig.sqlite()；Memory 下周期任务不会跨重启恢复。

Docker 部署

NeoTask 随应用进程启动，因此镜像构建的是「你的应用 + neotask 依赖」。以下是通用 Dockerfile：

FROM python:3.12-slim

ENV PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

# SQLite 默认路径 /data/neotask.db，挂载持久卷
RUN mkdir -p /data && chown -R 10001:10001 /data
USER 10001

CMD ["python", "-m", "myapp.worker"]

requirements.txt 中按需声明 neotask[redis] 或 neotask[monitor]。应用代码需处理 SIGTERM：收到信号后调用 pool.shutdown(graceful=True, timeout=30)，让执行中的任务完成、队列状态落库。

docker build -t myapp-worker .
docker run --rm -v neotask-data:/data --env-file .env myapp-worker

Docker Compose

多节点共享队列时，用 Compose 启动 Redis 与两个对等 Worker：

services:
  redis:
    image: redis:7-alpine
    command: ["redis-server", "--appendonly", "yes", "--requirepass", "${REDIS_PASSWORD}"]
    volumes:
      - redis-data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 10s
      timeout: 3s
      retries: 5

  worker-a:
    build: .
    command: ["python", "-m", "myapp.worker"]
    environment:
      NEOTASK_REDIS_URL: "redis://:${REDIS_PASSWORD}@redis:6379/0"
      NEOTASK_CONCURRENCY: "8"
    depends_on:
      redis:
        condition: service_healthy
    stop_grace_period: 40s

  worker-b:
    build: .
    command: ["python", "-m", "myapp.worker"]
    environment:
      NEOTASK_REDIS_URL: "redis://:${REDIS_PASSWORD}@redis:6379/0"
      NEOTASK_CONCURRENCY: "8"
    depends_on:
      redis:
        condition: service_healthy
    stop_grace_period: 40s

volumes:
  redis-data: {}

worker-a / worker-b 使用同一份代码、同一队列，无需主从配置。每个进程的 node_id 默认包含 pid，容器内也天然唯一。

生产环境部署

形态存储适用规模注意点
单进程嵌入SQLite低并发、单机保持单写入者；定期备份
多进程单机SQLite 只读查询 + 单写进程中等并发避免多进程同时写同一文件
多节点共享队列Redis横向扩展Redis 高可用、锁与心跳参数
调度 + 执行分离Redis / SQLite周期任务较多周期任务只由一个调度实例注册

生产建议：

  • 与 Web 服务分离部署：Web 进程只提交任务，Worker 进程执行，避免长任务占用请求线程。
  • 设置 task_timeout 与足够的 ttl；长任务同时调大两者。
  • K8s 中把 terminationGracePeriodSeconds 设为大于 shutdown(timeout)，确保优雅退出。
  • 开启指标与健康检查；探针使用 get_health_status()，不要用 get_stats() 做高频探针。
  • 生产为 event_queue_max_size 设置上限，避免慢回调导致内存增长。
  • 周期性任务只在一个实例注册，或使用 Redis 后端的周期任务持久化与互斥。
  • 需要自动回收崩溃节点任务时使用 Redis 后端；Memory / SQLite 模式没有心跳与回收器，进程异常退出后需人工处理遗留的 running 记录。

环境变量

NeoTask 不直接读取环境变量，但应用侧通常按以下变量装配配置：

变量示例用途
NEOTASK_STORAGEredis选择后端
NEOTASK_REDIS_URLredis://:pass@redis:6379/0Redis 连接
NEOTASK_SQLITE_PATH/data/neotask.dbSQLite 路径
NEOTASK_CONCURRENCY8Worker 并发
NEOTASK_NODE_IDworker-a可选，覆盖自动节点 ID

映射代码见 配置文档 · 环境变量。密码与连接串应通过 Secret 注入，不要写入镜像或日志。

存储与数据库

后端优势限制备份方式
Memory零配置、最低延迟进程退出即丢失；不跨进程无需备份
SQLite单文件、事务、易备份单写入者；不适合网络文件系统sqlite3 .backup 或文件快照
Redis多节点共享、低延迟需运维；内存容量约束RDB / AOF 与托管快照
  • SQLite 文件放在本地持久盘，不要放在 NFS / SMB 等网络挂载上。
  • Redis 建议开启 AOF 或定期 RDB；任务与事件需要可接受的丢失窗口。
  • 终态记录按 ttl 或 terminal_retention_seconds 清理；需要长期审计时在事件回调中导出。
  • 1.2.1 对 1.0.x 的 SQLite 老库会自动补齐缺失列；跨存储迁移仍使用仓库中的迁移脚本。

网络配置

  • Redis：生产启用认证与 TLS（rediss://），限制安全组仅允许 Worker 网段访问。
  • 超时：Redis 连接池上限由 redis_max_connections（默认 50）控制，按节点并发与副本数核算。
  • 延迟：跨可用区 Redis 会增加提交与心跳延迟；对延迟敏感时与 Worker 同区域部署。
  • SQLite：仅本地文件访问，不涉及网络端口；容器内通过卷挂载。
  • 健康检查：由应用暴露 HTTP 探针，内部调用 get_health_status()，不要把 Redis 端口直接暴露给探针系统。

安全部署

  • 容器以非 root 用户运行，根文件系统只读，仅挂载数据卷可写。
  • Redis 必须设置密码；不要把 6379 暴露到公网。
  • 任务 data、result 与断点会落库，避免存放明文凭证；必要时业务侧加密。
  • 执行器通过代码注册，禁止根据外部输入动态导入模块或执行任意代码。
  • 限制 SQLite 文件与备份的读权限；备份文件同样包含业务数据。
  • 升级前阅读发布说明，关注默认值变化与安全修复。

升级指南

  1. 阅读发布说明：确认目标版本的默认值、弃用项与行为变化。
  2. 备份存储：SQLite 复制数据库文件；Redis 触发一次快照。
  3. 先在预发验证：用相同配置跑一轮提交、重试、取消与恢复用例。
  4. 升级依赖：pip install -U "neotask[redis,monitor]"，确认 neotask.__version__。
  5. 滚动重启：多节点环境逐个重启；旧节点退出前完成优雅关闭，新节点接管队列。
  6. 观察指标：重点看队列深度、最老待处理任务年龄、失败率与回收次数。

SQLite 升级只支持「新增列 + 默认值」的自动补齐。跨大版本或跨后端迁移前先备份，并在预发环境验证脚本；不要直接对生产库试跑迁移。
