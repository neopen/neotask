任务锁用于避免同一任务被多个节点同时执行。默认使用内存锁，只在进程内有效；跨节点互斥必须使用 Redis 锁。

启用

from neotask import TaskPool, TaskPoolConfig

config = TaskPoolConfig(
    storage_type="redis",
    redis_url="redis://10.0.0.10:6379/0",
    node_id="worker-1",
    lock_type="redis",       # 关键：显式开启跨节点锁
    lock_timeout=30,
)
pool = TaskPool(executor=handle, config=config)
默认值陷阱：lock_type 默认是 "memory"，即使 storage_type="redis" 也不会自动改为 Redis 锁。仅在单进程内运行时，内存锁足够；多节点部署必须设置 lock_type="redis"。

自动加锁

Worker 在执行每个任务前自动获取锁，键为 lock:task:{task_id}（RedisLock 前缀 lock:），任务结束后释放。

属性行为
TTL自动加锁固定 30 秒
续期看门狗每 TTL × 0.3（最小 0.5 秒）续期一次
释放Lua 脚本校验 owner 后删除，避免误删他人锁
获取失败本次执行直接跳过，任务保持 pending

锁在任务开始时获取、结束时释放，不覆盖排队阶段。因此同一个任务不会被两个 Worker 同时开始执行；但执行超时、节点失联后的重复执行仍可能发生，业务侧必须保证幂等。

手动加锁

if pool.acquire_lock("report-2026-10", ttl=60):
    try:
        generate_report()
    finally:
        pool.release_lock("report-2026-10")
方法说明
acquire_lock(task_id, ttl=30)获取 task:{task_id} 锁，返回是否成功
release_lock(task_id)释放本实例持有的锁

手动锁与自动任务锁使用同一命名空间。不要用正在执行的任务 ID 作为手动锁键，否则会与 Worker 争锁。

实现细节

环节实现
加锁SET key owner NX EX ttl
解锁Lua：值等于 owner 才 DEL
续期Lua：值等于 owner 才 EXPIRE
owner每个锁实例生成随机 UUID，保存在进程内
非重入：同一实例重复获取同一把锁会失败。需要重入语义时，应在业务层合并临界区，而不是重复调用 acquire_lock()。

正确性边界

  • 锁保证“同一时刻只有一个持有者”，不保证任务只执行一次。执行超时、进程暂停（GC、容器冻结）或网络分区都可能造成重复执行。
  • 看门狗只能在本进程存活时续期；进程被杀后锁会在 TTL 内自动过期。
  • Redis 主从切换可能丢失未同步的锁写入，强一致场景需要 Redis 集群/Redlock 等额外方案，当前版本未内置。
  • 锁 TTL 与任务时长不匹配时，长任务可能在执行期间失去锁。自动锁固定 30 秒并持续续期，手动锁需要自行设置足够的 ttl。
