多节点部署使用 Redis 作为共享存储。所有节点消费同一个队列，没有主节点、选主或任务指派；任意节点都可以提交和执行任务。

前置条件

  • 所有节点连接同一个 Redis 数据库，并设置唯一 node_id；
  • 安装 neotask[redis]；
  • 各节点代码与任务数据格式一致；
  • 业务任务可安全重复执行。
pip install "neotask[redis]"

节点配置

from neotask import TaskPool, TaskPoolConfig

config = TaskPoolConfig(
    storage_type="redis",
    redis_url="redis://10.0.0.10:6379/0",
    node_id="worker-1",          # 每个节点必须唯一
    lock_type="redis",           # 跨节点互斥必须显式开启
    worker_concurrency=20,
    heartbeat_interval=5,
    heartbeat_timeout=20,
    reclaimer_interval=30,
)
pool = TaskPool(executor=handle, config=config)
pool.start()
锁类型不会自动切换：TaskPoolConfig.redis() 只设置存储，lock_type 仍默认为 "memory"。多节点部署必须显式设置 lock_type="redis"，否则任务锁只在进程内有效，无法阻止重复执行。

运行方式

在每台机器启动相同进程即可。提交到任意节点的任务都会进入共享队列，由最先取到任务的节点执行。

             ┌──────────── Redis ────────────┐
             │ queue:priority   task:*       │
             │ neotask:nodes    lock:*       │
             └───────▲───────────▲───────────┘
                     │           │
          ┌──────────┴──┐   ┌────┴──────────┐
          │  worker-1   │   │  worker-2     │
          │ TaskPool    │   │ TaskPool      │
          └─────────────┘   └───────────────┘

节点发现

能力说明
注册启动时写入 neotask:node:{node_id} 并加入 neotask:nodes
心跳默认每 5 秒刷新，键的过期时间为心跳超时的 2 倍
存活判定超过 heartbeat_timeout（默认 20 秒）未刷新视为失联
查询pool.get_active_nodes() 返回节点 ID、主机名与进程号
 
pool.get_active_nodes()
# [{"node_id": "worker-1", "hostname": "host-a", "pid": 1234}, ...]

无主架构

  • pool.is_leader() 始终返回 False，不存在领导者；
  • 任务不绑定提交节点，可能在任意节点执行；
  • 节点宕机后，其运行中的任务由存活节点回收并重新入队；
  • 队列只保证出队顺序，不保证跨节点完成顺序。

定时任务的多节点限制

TaskScheduler 没有选主或分布式去重。多个调度器实例注册相同周期任务时，每个实例都会按自己的时钟触发，导致重复执行。

  • 周期任务只在一个调度器实例上注册；
  • 或让周期任务本身具备幂等性，并在业务侧加分布式互斥；
  • 仅需即时任务的节点使用 TaskPool 即可，不要启动 TaskScheduler。

扩缩容

操作步骤
扩容启动新节点并设置新的 node_id；自动开始消费共享队列
缩容调用 shutdown(graceful=True)，等待队列清空后退出
强制下线直接终止进程；心跳超时后其他节点回收其任务
