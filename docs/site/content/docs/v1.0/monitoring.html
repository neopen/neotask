NeoTask 提供任务指标、健康检查与指标上报三类能力。核心指标都是进程内数据，默认不启动 HTTP 端点；需要界面或 JSON 入口时，可手动启用轻量 WebUIServer。

统计快照

stats = pool.get_stats()
print(stats["queue_size"], stats["completed"], stats["failed"])
print(stats["metrics"]["p95_execution_time"])
字段说明
queue_size优先队列与延时队列中的任务总数
total / pending / running按存储统计的任务数量
completed / failed / cancelled终态任务数量
success_rate成功 / (成功 + 失败)
node_id当前节点标识
metrics指标摘要；仅 enable_metrics=True 时存在
reclaimer回收统计；仅 Redis 模式存在
prefetcher预取统计；仅启用预取时存在

TaskScheduler.get_stats() 在相同字段上追加 periodic 与 time_wheel。

事件总线状态

bus = pool.event_bus.get_stats()
# {
#   "queue_size": 0,
#   "max_queue_size": None,
#   "processed_events": 12034,
#   "dropped_events": 0,
#   "slow_handler_calls": 0,
#   "slow_handler_threshold": 1.0,
#   "is_running": True
# }
字段说明
queue_size当前待处理事件数；持续上涨说明消费跟不上生产
max_queue_size配置的上限；None 表示无界
processed_events已分发事件总数
dropped_events有界队列满时丢弃的事件数
slow_handler_calls超过阈值的回调次数
slow_handler_threshold慢回调告警阈值（秒）
is_running事件消费任务是否在运行
指标依赖事件时序：metrics.throughput 与完成计数由生命周期事件推导。事件总线异步化后，慢订阅者会延后 task.completed 的观测时刻，使短窗口吞吐和延迟看起来偏低。排查时同时查看 queue_size 与 slow_handler_calls，不要把事件积压误判为任务执行慢。
终态清理影响计数：默认每 60 秒清理过期终态任务，completed / failed / cancelled 是当前存储中的记录数，不是历史累计值。累计口径请看 metrics.total_completed 等计数器。

任务指标

指标说明
total_submitted提交总数
total_completed / total_failed / total_cancelled终态计数
total_retried重试次数
pending / running瞬时数量
avg_execution_time、p50/p90/p95/p99_execution_time执行耗时，来自最近 1000 个样本
avg_queue_time、p95_queue_time排队耗时
throughput按完成事件计算的吞吐
priority_counts各优先级提交数量
systemCPU、内存、线程数等；需要 psutil
采样窗口：耗时分位数基于滑动窗口（默认 1000 条），不是全量历史。窗口填满后旧样本会被丢弃，长尾指标需结合外部监控系统。

健康检查

health = pool.get_health_status()
# {
#   "status": "healthy" | "degraded" | "unhealthy",
#   "node_id": "...",
#   "checks": {...},
#   "active_nodes": 2,
#   "heartbeat": {...},
#   "reclaimer": {...}
# }
检查项内容
storage存储可读写
queue队列是否可用、是否接近容量上限
systemCPU、内存、磁盘使用率；超过 90% 记为 degraded；未安装 psutil 时跳过
  • 结果缓存 5 秒，短时间内重复调用不会重复执行检查。
  • 单项检查默认超时 5 秒，避免依赖不可达时阻塞调用方。
  • 任一检查 unhealthy 时总状态为 unhealthy；存在 degraded 时为 degraded。

控制台上报

config = TaskPoolConfig(enable_reporter=True)
pool = TaskPool(executor=handle, config=config)

启用后每 60 秒向控制台输出一次 get_stats() 摘要。它适合本地观察，不适合生产监控。

轻量监控入口（可选）

1.0.8 不会自动启动 Web 服务。需要 HTTP 指标入口时，安装 neotask[ui] 并手动启动 WebUIServer。它提供根页面与 /api/stats，后者返回 get_stats() 的结果。

from neotask.web.server import WebUIServer

server = WebUIServer(scheduler, host="127.0.0.1", port=8080)
server.start()   # 后台线程启动 uvicorn

# GET http://127.0.0.1:8080/api/stats
# 退出时调用 server.stop()
  • 这是轻量监控入口，不提供任务编排、编辑、鉴权或历史存储。
  • TaskPool / TaskScheduler 不会自动挂载它，需要自行实例化。
  • 默认只监听本机。暴露到其他主机前，请置于鉴权代理之后。

Prometheus

库内提供 PrometheusReporter，通过 Pushgateway 推送指标，不暴露 /metrics 端点。

from neotask import ReporterManager, PrometheusReporter

reporter = PrometheusReporter("http://pushgateway:9091", job_name="neotask")
manager = ReporterManager(interval=60)
manager.add_reporter(reporter)
manager.set_metrics_callback(pool.get_stats)
await manager.start()
额外依赖：PrometheusReporter 使用 aiohttp，它不在 NeoTask 的依赖或 extras 中，需要自行安装。上报字段仅包含提交/完成/失败/成功率、pending/running 以及平均与 P95 执行耗时。

事件驱动采集

指标由生命周期事件推导：task.created、task.started、task.completed、task.failed、task.cancelled、task.retry。因此指标只覆盖当前进程产生或消费的事件，跨节点汇总需要把各节点数据送到同一个监控系统。有界事件队列发生丢弃时，依赖事件的统计也会缺失对应记录。
