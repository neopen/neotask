存储后端决定任务记录、队列和周期定义在进程退出后是否保留。NeoTask 1.x 提供 memory、SQLite、Redis 三种实现，通过 storage_type 选择。

对比

memorySQLiteRedis
依赖无aiosqlite（基础依赖）neotask[redis]
任务记录进程内单文件Redis 键
队列堆表ZSET
跨进程共享否有限（同一文件）是
故障回收无无有
适用规模开发与测试单机低频多节点、高并发

memory

from neotask import TaskPool, TaskPoolConfig

pool = TaskPool(executor=handle, config=TaskPoolConfig.memory())

任务、队列、周期定义都只存在当前进程。进程退出后全部丢失，也不会创建心跳、回收器或死信队列。

SQLite

config = TaskPoolConfig.sqlite("/var/lib/neotask/neotask.db")
pool = TaskPool(executor=handle, config=config)

数据库包含三组表：

表内容
tasks任务数据、状态、优先级、节点、重试次数、结果、进度
queue待执行任务的 ID、优先级、入队时间
periodic_tasks / periodic_executions周期任务定义与执行记录（启用持久化时）
并发写入限制：1.0.8 为 SQLite 单连接写入加了串行锁，同一进程内的多个 Worker 并发提交不再报 database is locked，但写入仍是一个接一个执行，吞吐随 Worker 数增加而下降。实测 100 条突发：1 Worker 87.4 tasks/s、2 Worker 61.8 tasks/s、4 Worker 41.3 tasks/s。生产环境仍建议单写入者；需要高并发写入时改用 Redis。

路径必须可写，目录需提前存在。容器中建议挂载持久卷，不要放在容器临时层。

Redis

config = TaskPoolConfig.redis(
    "redis://127.0.0.1:6379/0",
    node_id="worker-1",
)
pool = TaskPool(executor=handle, config=config)

主要键空间：

键类型用途
task:{task_id}String / JSON任务记录
queue:priorityZSET优先队列，score 为优先级
queue:delayedZSET仓储层延时索引
lock:task:{task_id}String任务级互斥锁
neotask:nodesSet节点集合
neotask:node:{node_id}Hash节点信息与心跳
neotask:dead_letterList死信队列
periodic_task:{id}String周期任务定义
periodic_tasksSet周期任务 ID 集合

所有节点必须连接同一个 Redis 数据库，并使用唯一的 node_id。Redis 模式下会启用节点心跳、任务回收、死信队列与分布式锁。TaskPoolConfig.redis() 会自动把 lock_type 设为 "redis"；如果手工构造 TaskPoolConfig(storage_type="redis", ...)，lock_type 仍默认为 "memory"，跨节点部署必须显式改为 "redis"。

实际持久化范围

数据是否持久化说明
任务记录与结果是（SQLite / Redis）写入后跨重启保留；终态记录会按保留期清理
优先队列是（SQLite / Redis）未出队任务可恢复
周期任务定义是（需启用持久化）memory 模式除外
延时堆 / 时间轮否仅进程内，重启后等待中的任务不会自动入队
指标、事件、进度回调否运行时数据

清理

1.0.8 默认启用终态清理：每 terminal_cleanup_interval（默认 60 秒）扫描一次，删除超过保留期的 success / failed / cancelled 记录。保留期由 terminal_retention_seconds 决定，0 表示沿用任务自身 ttl（默认 3600 秒）。

config = TaskPoolConfig(
    enable_terminal_cleanup=True,
    terminal_cleanup_interval=60.0,
    terminal_retention_seconds=7 * 24 * 3600,  # 终态保留 7 天
)

# 手动触发一次清理，返回删除数量
pool.cleanup_terminal_tasks()

任务级 ttl 同时用于回收器判断 running 超时，因此它既影响故障回收，也影响默认的终态保留时长。需要长期保留审计记录时，应关闭自动清理或设置更大的 terminal_retention_seconds，并自行归档。死信队列仍按 dead_letter_ttl（默认 7 天）过期，不受终态清理影响。
