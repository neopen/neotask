每个任务从提交到结束只经历有限几个状态。状态保存在存储层，事件通过事件总线发布；同步 API 与异步 API 查询的是同一份记录。

状态

状态含义是否终态
pending已创建，等待 Worker 出队否
running已被某个节点取走并开始执行否
success执行完成且返回值已保存是
failed执行失败且重试已耗尽，或被回收器判定失败是
cancelled被显式取消是
scheduled枚举中预留；1.0 的延时任务在等待期间仍为 pending否

正常流转

submit()
  │
  ▼
pending ──► running ──► success
  │            │
  │            ├──► failed ──► pending（自动重试）
  │            │                 │
  │            │                 └──► failed（重试耗尽）
  │            │
  │            └──► failed（超时 / 回收）
  │
  └──► cancelled（未开始或运行中取消）

查询与等待

方法返回
get_status(task_id)状态字符串；任务不存在返回 None
get_task(task_id)完整记录，包含数据、优先级、进度、节点、重试次数、时间戳
get_result(task_id)task_id、status、result、error、创建与完成时间
wait_for_result(task_id, timeout=300)成功返回结果；失败、取消或超时抛出异常
wait_all(task_ids, timeout=300)逐项等待，返回 {task_id: result}；失败项为 {"error": "..."}
跨节点等待：wait_for_result() 除了监听本节点事件，还会按 0.2 秒间隔回查存储，因此任务在其他节点执行时也能及时返回。

事件

回调必须是异步函数，签名为 async def handler(event: TaskEvent)。事件先进入后台队列，再由 EventBus 的消费任务依次分发给订阅者；回调抛出的异常会被记录并吞掉，不会影响任务执行。

注册方法事件event.data
on_createdtask.created任务的完整字典
on_startedtask.started{"node_id": "..."}
on_completedtask.completed执行器的原始返回值
on_failedtask.failed{"error": "..."}
on_cancelledtask.cancelledNone
on_progresstask.progress{"progress": 0.5, "message": "...", "timestamp": ...}
on_reclaimedtask.reclaimed回收原因等信息
 
import asyncio
from neotask import TaskPool, TaskPoolConfig

async def on_completed(event):
    print("done", event.task_id, event.data)

pool = TaskPool(executor=handle)
pool.on_completed(on_completed)

事件总线背压

默认事件队列无界，生产速度只受内存限制。设置 event_queue_max_size 后，队列满时新事件会被丢弃并计数；单个回调超过 event_slow_handler_threshold 秒时会累加慢回调计数。丢弃事件不会改变任务状态，但会让依赖该事件的监控或后续流程漏掉一次通知。

config = TaskPoolConfig(
    event_queue_max_size=1000,        # None 表示无界
    event_overflow_policy="drop",    # 当前仅支持 drop
    event_slow_handler_threshold=0.5,
)
pool = TaskPool(executor=handle, config=config)

print(pool.event_bus.get_stats())
# queue_size / max_queue_size / processed_events / dropped_events
# slow_handler_calls / slow_handler_threshold / is_running
慢订阅者会延后事件时刻：事件由独立消费任务处理，task.completed 的观测时间可能晚于任务实际完成时间。需要精确执行耗时时，在任务体内打点或用 get_task() 的时间戳；不要把事件延迟当作执行延迟。

终态清理

1.0.8 起默认每 60 秒清理一次已过保留期的 success / failed / cancelled 任务，避免内存与存储随任务量无限增长。保留时长取 terminal_retention_seconds，为 0 时使用任务自身 ttl。

config = TaskPoolConfig(
    enable_terminal_cleanup=True,
    terminal_cleanup_interval=60.0,
    terminal_retention_seconds=0,     # 0 = 按任务 ttl 清理
)

# 立即清理已过保留期的终态任务，返回清理数量
removed = pool.cleanup_terminal_tasks()
清理只删除已过保留期的终态记录，不影响 pending / running 任务，也不等同于故障回收。需要长期保留审计记录时，关闭自动清理或把 terminal_retention_seconds 设为足够大的值，并自行归档。

进度上报

异步任务调用 report_progress()；线程执行器中的同步任务调用 report_progress_sync()。进度值会收敛到 0 至 1，任务成功后自动置为 1.0。

from neotask import report_progress, report_progress_sync

async def async_task(data):
    await report_progress(0.3, "解析输入")
    await asyncio.sleep(1)
    await report_progress(0.8, "写入结果")
    return {"ok": True}

def thread_task(data):
    report_progress_sync(0.5, "处理中")
    return {"ok": True}
进程执行器运行在独立进程中，无法共享进度上下文，report_progress() 会返回 False。

取消、重试与删除

操作行为限制
cancel(task_id)从队列移除并置为 cancelled仅 pending / running 可取消；正在执行的业务代码不会被强制终止
retry(task_id, delay=0)把终态任务重置为 pending 并重新入队仅 failed / cancelled 可重试；retry_count 保留
delete(task_id)删除任务记录并清理等待者不会停止已经开始执行的代码
自动重试：执行失败后，若 retry_count < max_retries，任务回到 pending 并以 retry_delay × n 的延迟重新入队。重试耗尽后写入 failed，Redis 模式下同时投递死信队列。
