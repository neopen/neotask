The public entry points are TaskPool and TaskScheduler. Unless noted otherwise, every synchronous method has an _async counterpart with the same parameters and return value. This documentation is based on 1.2.1; methods and events marked 1.1 and 1.2 are additions from those releases.

from neotask import TaskPool, TaskScheduler, TaskPoolConfig, SchedulerConfig

TaskPool

TaskPool(executor=None, config=None)

executor can be a plain function, a coroutine function or a TaskExecutor instance; when it is None, a default executor that returns a fixed result is used.

Checkpoint resume (1.1)

MethodDescription
save_checkpoint(task_id, state)Save a full state snapshot and return the new version number; returns 0 if the task does not exist or checkpointing is disabled
load_checkpoint(task_id)Read the latest checkpoint; returns None if none exists or checkpointing is disabled

Inside executors use the module-level functions: await save_checkpoint(state) / await load_checkpoint() for async tasks, and save_checkpoint_sync() / load_checkpoint_sync() for threaded tasks; with a process executor, the parent process calls the methods above. See Checkpoint resume.

Cost, failure and relations (1.1)

MethodDescription
get_children(task_id)Return child task IDs for a parent_task_id, ascending by creation time
get_parent(task_id)Return the parent task ID, or None when there is none
report_failure(task_id, reason, detail="")Terminate a task from outside when a business rule fails; applies to running tasks only and does not enter automatic retry
report_cost(task_id, tokens_in=0, tokens_out=0, api_calls=0, estimated_cost=None, currency=None)Accumulate task cost; terminal tasks can also be updated

Inside executors use report_failure(reason, detail) and report_cost(...); both are synchronous functions. See Failure recovery and Cost and duration.

Blackboard (1.1, memory only)

MethodDescription
context_set(key, value, ttl=None)Write to the in-process shared context; ttl is in seconds and None means no expiry
context_get(key)Read a value; returns None if it is missing or expired
context_delete(key)Delete a key; returns whether it was present

Calling these on a non-memory backend raises UnsupportedFeatureError. The scope is the current TaskPool instance; values do not cross processes and are not persisted. See Task relations and shared context.

get_metrics() reads counters and aggregate queries only and suits probes and high-frequency reporting; when you need full task detail, use get_stats() or get_task() instead. See Monitoring and health checks.

TaskScheduler

TaskScheduler(executor=None, config=None)

It creates a TaskPool internally and adds delayed, periodic and Cron scheduling. Apart from sync-only items such as get_periodic_*, the methods below also have _async versions.

CLI and lightweight benchmarks

Since 1.0.8 the installed package provides a neotask entry point, equivalent to python -m neotask:

neotask --version
neotask --help
neotask --benchmark --tasks 2000 --concurrency 10 --json
OptionDescription
--executor MODULE:FUNCExecutor; also accepts a file path form such as ./bench.py:func
--tasks / --concurrencyTask count and worker concurrency, 200 / 10 by default
--warmup / --timeoutNumber of warmup tasks and the wait timeout
--payloadJSON task data template, {"index": i} by default
--no-prefetchDisable worker prefetch
--jsonEmit JSON for CI or scripts to consume

From code, call run_benchmark() / run_benchmark_async(), which return a BenchmarkResult; benchmarks disable health checks, metrics and reporters by default.

Other exports

neotask also exports executor, storage, queue, lock, monitoring and distributed components: AsyncExecutor, ThreadExecutor, ProcessExecutor, MemoryTaskRepository, SQLiteTaskRepository, RedisTaskRepository, MemoryCheckpointRepository, SQLiteCheckpointRepository, RedisCheckpointRepository, PriorityQueue, DelayedQueue, MemoryLock, RedisLock, WatchDog, MetricsCollector, HealthChecker, NodeManager, Coordinator and more.

The executor-scoped functions added in 1.1, report_failure, report_cost, save_checkpoint, load_checkpoint, and the synchronous variants save_checkpoint_sync and load_checkpoint_sync, are exported directly as well. See neotask.__all__ for the complete list.
