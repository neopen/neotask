NeoTask configuration is provided by two dataclasses: TaskPoolConfig for immediate tasks and SchedulerConfig for delayed and periodic tasks. Every field has a default, so a direct instantiation is enough to run.

from neotask import TaskPool, TaskPoolConfig

config = TaskPoolConfig(
    storage_type="redis",
    redis_url="redis://127.0.0.1:6379/0",
    lock_type="redis",       # must be set explicitly when built by hand; the redis() factory sets it automatically
    worker_concurrency=20,
    task_timeout=60,
    max_retries=3,
)
pool = TaskPool(executor=handle, config=config)

The switches take effect since 1.0.8: enable_reclaimer and enable_heartbeat now directly decide whether the reclaimer and heartbeat components are created, and they only apply when storage_type="redis" and redis_url is configured. Turning off the heartbeat also loses the node liveness view, and orphan reclamation is skipped.

Configuration is only passed down in part: TaskScheduler passes storage, worker_concurrency, retries, checkpoint, progress write-back, cache limits, shutdown delay handling and event bus fields to the internal TaskPool, and sets the lock type according to the storage type. Prefetch, monitoring, task_timeout, queue capacity, dead letter and other parameters still require constructing TaskPool directly or modifying the underlying config; SchedulerConfig does not expose these fields today.

Common presets

ScenarioConfiguration
Local developmentTaskPoolConfig.memory()
Single-machine persistenceTaskPoolConfig.sqlite("/var/lib/neotask.db"); writes are already serialized, but a single writer is still recommended
Shared queue across nodesTaskPoolConfig.redis("redis://host:6379/0", node_id="worker-1")
Scheduled tasksSchedulerConfig.redis("redis://host:6379/0") or SchedulerConfig.sqlite(path)
Low-latency delayed tasksSchedulerConfig.high_performance() (time wheel enabled)

Environment variables

This version does not read environment variables; all configuration is passed in code. In containerized deployments, construct the configuration object explicitly in your startup script.
