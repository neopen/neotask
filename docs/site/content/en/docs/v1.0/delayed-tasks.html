Delayed tasks run once at a specific point in time; periodic tasks repeat on an interval or a Cron schedule. Both are provided by TaskScheduler and reuse TaskPool underneath for execution and storage.

One-off delay

from datetime import datetime, timedelta
from neotask import TaskScheduler

scheduler = TaskScheduler(executor=send_reminder)

# relative delay
task_id = scheduler.submit_delayed({"user_id": 42}, delay_seconds=300)

# fixed point in time
run_at = datetime.now() + timedelta(hours=2)
task_id = scheduler.submit_at({"user_id": 42}, execute_at=run_at)
ParameterDefaultDescription
delay_secondsRequiredDelay in seconds; a value of 0 or less enqueues the task immediately
task_idGenerated automaticallyCustom IDs must be unique
priorityNORMALPriority used when the task is enqueued at expiry
ttl3600Task-level timeout / reclaim threshold

Time wheel

With SchedulerConfig(enable_time_wheel=True), a delayed task is first written to storage (status pending) and then added to the time wheel. At expiry only the task is pushed into the queue, so while it waits it can still be queried and cancelled by task ID.

from neotask import TaskScheduler, SchedulerConfig

config = SchedulerConfig.high_performance()  # 360 slots × 1 second
scheduler = TaskScheduler(executor=handle, config=config)
scheduler.start()
  • The default range is slots × tick × max_rounds, that is 60 × 1 second × 100 rounds ≈ 100 minutes.
  • A delay beyond that range falls back to the regular delayed queue and is not lost.
  • The time wheel itself is not persisted, so unexpired tasks are not enqueued automatically after a process restart.

Cron

report_id = scheduler.submit_cron(
    {"job": "daily-report"},
    "0 9 * * *",          # every day at 09:00
    name="daily-report",
    max_runs=None,
    missed_policy="run_once",
)

Cron expressions are parsed by croniter and support the standard five-field format. The first execution happens at the next matching time; it does not run immediately.

missed_policyBehavior
skipSkip all missed slots and continue from the current time (default)
ignoreIgnore missed slots; similar to skip
run_onceRun exactly once to catch up after a miss
catch_upReplay missed slots, up to 5 executions per round

Persistence

StoragePeriodic tasks across restartsDelayed tasks across restarts
memoryNo; a warning is logged once at registrationNo
SQLiteYes, with enable_persistence=TrueNo; unexpired tasks are not enqueued automatically
RedisYes, with enable_persistence=TrueNo; unexpired tasks are not enqueued automatically
Restart boundary: Task records are preserved, but the delayed heap and the time wheel live in process memory. After a restart, delayed tasks still in their waiting period remain pending and do not run automatically. The application must scan and resubmit them at startup, or express the recurring schedule as a periodic task instead.

Shutdown

scheduler.shutdown(graceful=True, timeout=30)

Graceful shutdown first stops accepting new tasks, waits for the queue to drain, then stops the periodic manager and the time wheel.

1.0.8 adds drain_delayed_on_shutdown (default False). When enabled, delayed tasks that have not yet expired are moved into the priority queue at shutdown and awaited. This suits workloads where running early is preferable to losing a task; the trade-off is that those tasks no longer run at their scheduled time.
