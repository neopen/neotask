NeoTask has a small integration surface: create a pool inside your application process, submit tasks, and optionally subscribe to events or query metrics. The difficulty is not wiring it up but deciding which work should become asynchronous and how results flow back into the business.

Integrating with business systems

Split a business action into three layers:

  1. Entry layer: a web request, message consumer or CLI validates and submits, then returns a task_id.
  2. Execution layer: a worker calls domain services to perform the slow work.
  3. Write-back layer: event callbacks or polling write status back to business tables or notify the frontend.
from neotask import TaskPool

pool = TaskPool(executor=handle_export)

def request_export(user_id: str, query: dict) -> str:
    return pool.submit({"user_id": user_id, "query": query}, priority=1)

Do not depend on request context (sessions, request objects) inside a task. Serialize the needed parameters into data and let the worker reload its resources.

HTTP / API integration

Typical flow: the submit endpoint returns a task ID, a query endpoint reads status, and completion events handle callbacks or write results.

from fastapi import FastAPI, HTTPException
from neotask import TaskPool

app = FastAPI()
pool = TaskPool(executor=handle)

@app.post("/exports")
def create_export(payload: dict):
    task_id = pool.submit({"query": payload}, priority=1)
    return {"task_id": task_id, "status": "queued"}

@app.get("/tasks/{task_id}")
def get_task(task_id: str):
    result = pool.get_result(task_id)
    if result is None:
        raise HTTPException(status_code=404, detail="task not found")
    return result
  • Keep submit endpoints idempotent: derive a request key in the business layer so double clicks do not create duplicate tasks.
  • Query endpoints are read-only and trigger no side effects; for waiting, use short polling or SSE instead of blocking an HTTP request.
  • Return 202 Accepted with the task query URL so the frontend can render progress.
  • Pair rate limiting with queue capacity: when the queue is full return 429 or a degraded message instead of retrying forever.

Python integration

When integrating in Python code, first decide whether a running event loop is already present:

ContextRecommended APIWhy
Scripts, sync functionssubmit() / wait_for_result()Drives the background loop safely
Async services, coroutinessubmit_async() / wait_for_result_async()Avoids nested event loops
Framework lifecyclewith / async withGuarantees shutdown and resource release
Application startup hookpool.start()Warms up workers and storage connections
 
from contextlib import asynccontextmanager
from fastapi import FastAPI
from neotask import TaskPool, TaskPoolConfig

@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.pool = TaskPool(executor=handle, config=TaskPoolConfig.sqlite("/data/app.db"))
    yield
    app.state.pool.shutdown(graceful=True, timeout=30)

app = FastAPI(lifespan=lifespan)

Sync frameworks such as Django / Flask can create the pool during initialization and close it in an exit hook. With multi-process deployment (gunicorn workers), keep SQLite single-writer or switch to Redis.

Third-party SDKs are often not thread-safe. With ThreadExecutor or high concurrency, create a client per execution context, or use a connection pool you have verified to be concurrency-safe.

Agent integration

A single agent tool call is usually slow, costs money and may fail and retry, which is exactly what NeoTask covers:

from neotask import TaskPool, report_progress, report_cost

async def run_agent_step(data):
    for i, step in enumerate(data["steps"]):
        await report_progress((i + 1) / len(data["steps"]), step["name"])
        result = await call_tool(step)
        await report_cost(
            tokens_in=result.usage.input_tokens,
            tokens_out=result.usage.output_tokens,
            api_calls=1,
            estimated_cost=result.cost,
            currency="USD",
        )
    return {"ok": True}

pool = TaskPool(executor=run_agent_step)
parent = pool.submit({"steps": plan}, priority=0)
for sub in subtasks:
    pool.submit({"steps": [sub]}, parent_task_id=parent)
  • Priority: interactive conversations use CRITICAL; batch analysis uses LOW.
  • Cost: accumulate tokens and spend with report_cost(), then aggregate with get_cost_summary().
  • Recovery: call save_checkpoint() after each step of a multi-step agent so it does not rerun everything.
  • Parent/child links: build the call tree with parent_task_id; aggregating status and cost is the caller's job.

Workflow integration

NeoTask executes single tasks and does not parse a DAG. The workflow belongs to a control plane above it:

# An orchestration layer such as NeoFlow decides dependencies and branches
for node in ready_nodes(dag):
    task_id = pool.submit(
        {"node": node.name, "inputs": node.inputs},
        priority=node.priority,
    )
    dag.mark_submitted(node.name, task_id)

# Completion events drive the next step
async def on_completed(task):
    dag.mark_done(task.task_id, task.result)
    for nxt in dag.ready_after(task.task_id):
        pool.submit({"node": nxt.name, "inputs": nxt.inputs})

The benefit: orchestration logic is tested and evolved independently, NeoTask keeps stable execution semantics, and workflow state does not depend on task-record retention.

Integration examples

Webhook delivery with retries

import httpx
from neotask import TaskPool, TaskPoolConfig

async def deliver(data):
    async with httpx.AsyncClient(timeout=10) as client:
        resp = await client.post(data["url"], json=data["payload"])
        resp.raise_for_status()
        return {"status": resp.status_code}

pool = TaskPool(
    executor=deliver,
    config=TaskPoolConfig(max_retries=5, retry_delay=2.0),
)
pool.submit({"url": "https://example.com/hook", "payload": {"id": 1}}, priority=1)

Scheduled sync plus metric reporting

from neotask import SchedulerConfig, TaskScheduler

scheduler = TaskScheduler(
    executor=sync_catalog,
    config=SchedulerConfig.redis("redis://redis:6379/0"),
)
scheduler.submit_interval({"source": "catalog"}, interval_seconds=300, name="catalog-sync")

def push(snapshot):
    statsd.gauge("neotask.queue.pending", snapshot["pending"])
    statsd.gauge("neotask.oldest_pending_age", snapshot["oldest_pending_age_seconds"] or 0)

scheduler.on_metrics(push, interval=10)

Write results back to a business table

async def on_completed(task):
    await db.execute(
        "UPDATE exports SET status='done', file=:file WHERE task_id=:id",
        {"id": task.task_id, "file": task.result["file"]},
    )

pool.on_completed(on_completed)
