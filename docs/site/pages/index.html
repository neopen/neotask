WHY NEOTASK

轻量，但不简陋。

为耗时任务设计的嵌入式任务运行时：从单进程后台任务到多节点共享队列，保持同一套 API 与同一份心智模型。

少一个中间件，少一类故障

默认使用内存或 SQLite，应用启动即用。不必为了几十个后台任务，再维护一套 Broker、Worker 与监控组件。

你的应用 → TaskPool → SQLite

从单进程到多节点，不换 API

一个配置工厂切换到 Redis 共享队列：节点对等、抢占消费，心跳与回收自动接管异常节点留下的任务。

node-1 node-2 node-3 Redis Queue

默认可观测，失败可回收

生命周期事件、指标与健康检查开箱可用；失败自动重试，超时与宕机任务由回收器重新入队。

提交并等待结果

定义异步执行器，创建 TaskPool，提交任务。同步、异步与上下文管理器三种用法按需选择。

  • 自动启动后台事件循环
  • 支持结果等待与状态查询
  • 退出时优雅关闭

延时、周期与 Cron

TaskScheduler 在 TaskPool 之上提供调度能力，三种定时方式共用同一个执行器。

  • 延迟执行与指定时刻执行
  • 固定间隔周期任务
  • Cron 表达式与暂停/恢复

切换到共享队列

用配置工厂切换到 Redis：多节点消费同一队列，心跳、回收与任务锁自动生效。

  • 节点对等，无主架构
  • Redis 锁与看门狗续期
  • 可选预取提升吞吐

from neotask import TaskPool

async def process_order(data):
    # 耗时业务逻辑
    await asyncio.sleep(2)
    return {"status": "ok", "id": data["id"]}

pool = TaskPool(executor=process_order)

task_id = pool.submit({"id": "order_001"})
result = pool.wait_for_result(task_id, timeout=30)

print(result)
pool.shutdown()
from neotask import TaskScheduler

scheduler = TaskScheduler(executor=process_order)

# 60 秒后执行一次
scheduler.submit_delayed({"id": "123"}, delay_seconds=60)

# 每 5 分钟执行一次
scheduler.submit_interval(
    {"job": "heartbeat"},
    interval_seconds=300,
)

# 每天 9:00 执行
scheduler.submit_cron(
    {"job": "daily_report"},
    cron_expr="0 9 * * *",
)

scheduler.shutdown()
from neotask import TaskPool, TaskPoolConfig

cfg = TaskPoolConfig.redis(
    url="redis://localhost:6379/0",
    node_id="worker-1",
    lock_type="redis",
    enable_prefetch=True,
    prefetch_size=30,
)

pool = TaskPool(executor=process_order, config=cfg)

# 相同代码，多节点共享队列
task_id = pool.submit({"id": "order_002"})
result = pool.wait_for_result(task_id)

CHOOSE THE RIGHT TOOL

什么时候选 NeoTask？

NeoTask 不试图替代所有任务平台。它专注一件事：让 Python 应用以最低的运维成本，可靠地处理耗时任务。

维度NeoTaskCelery
部署依赖无需中间件，Redis 可选需要 Broker（Redis / RabbitMQ）
定位嵌入式轻量任务队列全功能分布式任务平台
定时任务内置延时、间隔、Cron需要 Celery Beat
优先级内置四级优先级通过多队列与路由实现
任务编排DAG 规划中（v1.5）Canvas / Chord 成熟
Web 监控可选 neotask[ui]Flower
生态与插件聚焦核心，轻量成熟、插件丰富

如果你的团队已经在 Celery 上运行复杂编排，继续使用它是合理的。NeoTask 适合希望减少基础设施、快速交付后台任务能力的 Python 项目。

FAQ

常见问题

还有疑问？在 GitHub Discussions 发起讨论。

NeoTask 需要额外部署 Redis 或消息队列吗？

不需要。默认使用内存或 SQLite 存储，安装后即可在应用进程内使用。只有需要多节点共享队列时，才需要切换到 Redis。

它和 Celery 有什么区别？

NeoTask 更轻：无需 Broker，内置定时、优先级和存储抽象，适合嵌入式场景。Celery 的生态、复杂任务编排和运维工具更成熟，适合已有大规模任务平台。

任务失败会自动重试吗？

会。通过 max_retries 与 retry_delay 配置重试次数和退避间隔；节点宕机留下的任务由回收器重新入队，最终失败的任务进入死信队列。

支持 Python 3.8 吗？

支持。基础包要求 Python ≥ {{PYTHON}}，依赖 aiosqlite、croniter 与 colorama；Redis、psutil 与 Web UI 为可选扩展，通过 neotask[redis]、neotask[ui] 或 neotask[full] 安装。

可以在生产环境使用吗？

可以。v1.0 起已具备持久化、故障恢复、分布式锁、死信队列与指标采集。建议使用 SQLite 或 Redis 持久化，并为关键任务配置重试与监控；上线前请阅读最佳实践。
