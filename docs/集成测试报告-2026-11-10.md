## 4. 缺陷与验证

### 4.1 唯一失败项：分布式用例计数口径（测试缺陷）

`tests/distributed/test_integration.py::test_full_distributed_workflow` 断言 `size == 20`，实际 19。

- **根因**：用例在分发任务前就启动了 `TaskPrefetcher`，预取器会把部分任务移入本地队列，而 `QueueScheduler.size()` 只统计共享队列；任务并未丢失。
- **修复**：断言改为 `size + prefetched == 20`，口径对齐。
- **复跑**：`tests/distributed` 112 passed / 2 skipped / 0 failed。

### 4.2 本轮代码修复的验证点

| 缺陷 | 修复 | 验证方式 |
|---|---|---|
| 同实例重启挂死 | `EventBus` / `TaskPrefetcher` 启动时重建 `asyncio.Queue`；`QueueScheduler.start()` 复位 `_disabled` | 同实例连续 start/shutdown 3 次（修复前挂死） |
| 事件循环线程泄漏 | `run_loop` 以 `try/finally` 关闭循环；`shutdown()` 停止并 join 线程 | 5 次启动/停止后线程数 1→1（修复前 1→6） |
| `TaskPool.cancel` 不中断运行中任务 | 先 `worker_pool.cancel_task()` 再标记状态 | 验收脚本：`active_count` 立即归零、终态 `cancelled`、执行体未完成 |
| `TaskEngine.submit` 默认优先级非法（`priority=5`） | 默认改为 `TaskPriority.NORMAL`，dispatcher 用 `from_value` 容错越界整数 | 验收脚本：默认优先级可用、越界 9 回落 NORMAL |
| redis 依赖无上界 | `neotask[redis]` 增加 `,<6` | 本次实测 redis-py 8.1.0 无法连接 Memurai 3.2 |

### 4.3 验收脚本覆盖（22 项全通过）

批量原子提交（`BatchSubmitError`）、`partial_on_error`、SQLite 批量原子写入、500 任务端到端、`drain_delayed_on_shutdown`、非 drain 模式告警、停机摘要、内部计数器、进度节流、写回 flush、`TaskEngine` 取消、`TaskPool` 取消（排队/运行中/不存在 ID）、越界优先级、`engine.submit_batch` 默认优先级、空批次、队列满部分提交。
